# 共通テスト形式 国語 第4問（古文）演習問題集 ―― 基礎から本番まで

共通テスト第4問（古文）だけを、やさしい説話から本番の分量まで **6回** 並べた演習問題集。
どの回も本番と同じ形（5問・45点・解答番号23〜29）で、読む本文の側だけを段階的に重くしてある。

| 回 | レベル | 出典 | 本文 | 目安 | 字/分 |
|---|---|---|---|---|---|
| 1 | 基礎 | 古本説話集 第四十四話（大隅守の事） | 499字 | 18分 | 28 |
| 2 | 基礎 | 宇治拾遺物語 第八十六話（清水寺に二千度参詣の者、双六に打入る事） | 641字 | 18分 | 36 |
| 3 | 標準 | 古今著聞集 第百七十七話（小大進） | 716字 | 19分 | 38 |
| 4 | 標準 | 無名抄 第十六話（ますほのすすき） | 801字 | 19分 | 42 |
| 5 | 本番 | 無名抄 第十七話（井手の山吹、并かはづ） | 945字 | 20分 | 47 |
| 6 | 本番 | 発心集 第六第七話（永秀法師、数寄の事） | 1031字 | 20分 | 52 |

階段は「本文が長くなること」ではなく **「1分あたりに読む量が増えること」** で作ってある。
時間も一緒に伸ばすと、進むほど時間的な圧力が下がって本番から遠ざかる（最初の版が実際にそうなっていた）。
本番の2回は、共通テストで古文にあてられる時間そのもの（20分）に置いている。

出力は 2 冊。**問題編＝縦書き**（本番と同じ体裁）／**解答解説編＝横書き**（解答一覧・設問別解説・
全文現代語訳・重要文法・使うルール）。ほかに講師用メモ（本文の典拠と校訂の記録）。

## 作り直す手順

```
PYTHONPATH=src python3 make_sets.py   # src/setN.py（原稿）-> sets/setN.json（刷る形）
python3 check_source.py               # 本文が原典どおりか
python3 check.py                      # 配点・解答番号・注・現代語訳・レベルの階段・正解の分布
python3 audit.py                      # 漏洩・引用の崩れ・位置の癖・正解肢の tell
python3 check_gates.py                # ★検査そのものが効いているかの変異試験（59種）
python3 build.py                      # out/ に PDF
python3 check.py out/...問題編.pdf out/...解答解説編.pdf   # 刷り上がりとデータの逆照合
python3 make_memo.py                  # 講師用メモを data から生成
python3 blind.py                      # 盲検証用（正解を伏せたもの）を blind/ に出す
python3 refetch_sources.py            # ★通信あり。sources/*.txt を公開ページから取り直して照合
```

`python3 ../run_all_gates.py kobun_kyotsu` でも check* / audit* がまとめて回る（CI と同じ入口）。

## 守ること

- **本文は原典から機械的に写す。記憶で書かない。** `sources/*.txt` は「やたナビTEXT」の
  校訂本文をそのまま保存したもので、**編集してはならない**。編集すれば `check_source.py` は
  ただの自己肯定になる。原典から改めた箇所は `sources/emendations.json` に理由つきで登録する
  （登録しないと通らない）。話の途中までを切り出した場合は `sources/cuts.json` に申告する。
- **正解の位置は `src/positions.py` が正典。** 手で振ると必ず偏る。設問を差し替えても
  この表は動かさない。分布は `check.py`、位置の癖は `audit.py` が毎回見る。
- **解説に丸数字（①②）を直接書かない。** 必ず `[[ア0]]`（執筆順の添字）で書く。
  直接書くと並べ替えで解説と選択肢がずれる。`make_sets.py` が丸数字に直す。
- **学説の分かれる論点は設問にしない。**（完了「り」の接続、「ず」の活用形、
  四段動詞に付く「なり」の識別など）。断定すると、どちらの教材で学んだ生徒かで正誤が変わる。
- **ゲートを足したら `check_gates.py` に変異を1つ足す。** ガードを消したときに
  そこが赤くならないなら、そのゲートは効いていない。
  ★変異試験は「赤になったか」ではなく **「狙った検査が拾ったか」** で判定する
  （期待する NG の文言を持たせてある）。以前は前者だけを見ていたため、
  **正解位置の検査9か所・レベルの階段5か所・校訂記録5か所を丸ごと消しても緑**だった。
  ★正解位置を壊す変異は、使い回しの写しではなく**毎回まっさらな写し**の中で回す
  （前の変異の残りやバイトコードのキャッシュで、変異が空振りしていた）。
- **正解肢の長さを、他の肢の真ん中に置く。** 単独最長・単独最短だけでなく
  **長さ順位の平均**（2.4〜3.6）も見る。初版は問2〜問5 の 24/24 が最長＝正解、
  直しすぎた版は逆に 64% が最短＝正解になった。どちらも「長さだけで絞れる」状態である。 直すときは正解を刈るのではなく**誤答を厚くする**
  （刈ると根拠が痩せる）。初版は問2〜問5 の 24/24 が最長＝正解で、本文を読まずに 30/45 点
  取れる状態だった。閾値だけの検査（1.30倍）は最大比 1.299 で一度も鳴らなかったので、
  `audit.py` は**割合**（単独最長が4割超で落とす）も併せて見る。
- **縦組みの体裁は第1版（`_legacy_build_202609.py` で刷った冊子）にそろえる。**
  塾長の手元にある冊子と流儀が違うと「別の教材」に見える。決まりは2つ。
  ① **見出しと配点は漢数字**（第四問（古文）／配点四五点／得点　／四五）。
     **解答番号・分・字数・設問番号・注番号は算用数字**（縦中横）のまま。本番の冊子も同じ使い分け。
  ② **傍線の記号は半角かっこの `(ア)` を縦中横で1マスに収める。**
     全角の `（ア）` を素の3字で置くと縦に3マス使い、本文の列がそこだけ押し下げられる。
     ★ただし縦中横は中身を 1em に押し込むので、`font-size` を小さく書くと実寸がさらに縮む。
     第1版は 8.5pt 指定＝**実寸 6.8pt** で注番号より小さかった。本文と同じ級数を指定すること。
  この2つは `check.py <PDF> <PDF>` の `check_style` が見る。★刷ったPDFを渡したときしか動かない
  ＝CI では一度も走らないので、判定表そのものの自己テスト（`selftest_style`）を毎回走らせ、
  さらに `check_gates.py` が「検査の中身を1つ消したら自己テストが鳴るか」を5種の変異で確かめる。
- **傍線・波線はかぎかっこ「」の内側に引く。** かっこを含めると、設問側の引用符と見分けがつかない。
  また **線を引いた範囲は、設問の引用と1字ずつ同じ**にする（注番号と読み仮名を除く）。
  ★開き1個・閉じ1個を数える検査では、引く位置のずれは**絶対に出てこない**。
  実際に6回中5回が『「いな、かくては受け取らじ』のように開きかっこから引き始めていて、
  4つのゲートすべてが緑だった。いまは `check.py` が範囲と引用を突き合わせる。
- **設問が本文を引用するとき、引用の中の会話は『』にする。** 「」の入れ子は引用の切れ目が読めない
  （第2回 問3 が『傍らにて聞く人は、「謀るなり」と…』で入れ子になっていた）。本文そのものは直さない。
- **空白ではないが数行しか無い紙を作らない。** 空白ページの検査は「0行」しか見ないので素通りする。
  典拠の1行だけが次ページへこぼれて2行の紙が1枚できた（解答解説編の最終ページ）。
  `check.py` が3行未満のページを落とす。
- **`sets/*.json` は生成物だが git に入っている。** 原稿 `src/*.py` を直して `make_sets.py` を
  回し忘れると、直したつもりの冊子がそのまま刷れる。`check.py::check_fresh` が
  **原稿から作り直して丸ごと比べる**。★項目を1つずつ数え上げる書き方にしないこと
  （最初にそう書いたら、解説・配点・解答番号・注の説明文・小問の末尾追加が全部素通りした）。
- **潰し文は1文で独立させる。「も」「これも」「同じく」で前の文を受けない。**
  ★潰し文は番号順に並べ替えられるので、**受け先が後ろへ回る**。
  「③ も妻を失ったことにしており、同じく結末と合わない。」が別の話の直後に刷られ、受け先が消えた。
  `check.py::anaphora_in_kill` が落とす（「いずれも」等のまとめ潰しは対象外）。
  ★「これも」だけを数えないこと。**壊れ方の側から数えている**ので、
  「これも本文にない」→「そのような記述**も**本文にない」と書き換えただけで素通りした。
- **N件で打ち切って印字するときは、溢れた分が何件かを必ず言い、「止めている行から」並べる。**
  ★件数を出すだけでは足りない。回番号の順に切ったら、いちばん的中率の高い1件が黙って落ちていた。
  ★黙って切ると「これで全部」に見える（回ごとの偏りの一覧で1件が黙って落ちていた）。
- **解説の「⑤ は…」が本当にその⑤について書かれているか。** 1文1肢に割るとき、
  **執筆順の添字（[[n]]）と述語の対応を取り違える**事故が実際に3か所起きた（刷る順から逆算して書く）。
  刷り上がりを読まないと気づけないので、`audit.py` が「解説がどれかの肢から言葉を引いているとき、
  その出どころが指している肢かどうか」を突き合わせる。
- **1つの設問の誤答4本すべてに出て正解に無い言い回しを作らない**（閾値の要らない見方）。
  第5回 問4 が実際にその形で、本文を読まずに当てられた。
- **余白の掃除は、掃除の前後で「字の隣にある罫」が減っていないことを確かめてから通す。**
  ★範囲を間違えて本物の傍線を消しても、消えた罫は「宙に浮いた罫」でも「墨の無い罫」でもなく
  **存在ごと無い**ので、どの検査にも映らない（`left_edge` を 70pt にすると傍線が8本消えても全部緑だった）。
- **刷ったPDFには刷るデータ**と**組版のコード**の指紋を焼く（`build.py::stamp` → PDFの keywords）。
  ★データだけだと「build.py を直したのに刷り直していないPDF」が素通りする。
  今日いちばん危なかったのは CSS の1行（`.u` の padding）だった。
  ★これが無いと `check.py <PDF>` が「いつ刷ったか分からないPDF」を検査して緑になる
  （データの全要素がPDFにあることは見るが、そのPDFが今のデータから刷られたかは見ていない）。
- **解説が誤答を潰す順は、読む順に並べて昇順にする。**
  ★かたまりの先頭と中だけを見ると、「②③⑤ のあとに ④」のような**飛び番号のかたまり**が通る。
  生徒は自分の番号を頭から探すので、④ を探す生徒が ⑤ を通り過ぎる。かたまりは連番だけにする。
- **解説の結論は「よって ⑤。」の形で書く。** ほかの書き方だと順の検査が何も拾えず黙って緑になる。
- **`sort_kills` が丸数字を並べ替えてよいのは「いずれも」等でまとめて潰すと明記した文だけ。**
  ★「いずれも」を足しただけでは足りない。述語が「・」「や」で並んでいると順に対応して読めるので、
  並べ替えで**意味が反転する**（「③ ④ はいずれも追いつめる・怒らせる」で実際に反転した）。
- **誤答だけに出る言い回しは、回ごとにも数える（MIN=8）。**
  ★6 に下げてはいけない。回の中は正解7本・誤答28本しかなく、`a=0` でも超幾何の p は b=6 で 0.23。
  **回の中だけで統計的に有意な tell は出せない**（6 だと順列検定400回で29%が誤報。合算の層は4%）。
  閾値に届かない偏りは落とさずに一覧で印字して人に回す。
  ★6回を合算すると薄まって見えない。実測で第5回は「てしまっ」が**その回の誤答28本中7本・正解0本**
  だったが、合算では a=2/b=11 でどのしきい値にも届かなかった。生徒は1回ずつ解く。
  正解側に寄る言い回しも同じだけ危ないので、判定は対称にする。
- **解説が誤答を潰す順は、かたまりの先頭も中も昇順にする。** 1文で2つ潰すと（「④ は…取り、⑤ は…」）
  並べ替えても番号が飛ぶので、**1文1肢に割る**か「いずれも」を付けてまとめて潰すことを明示する。
  ★`kill_order` は文頭の1字ではなく**丸数字を全数**拾う。文頭だけ見ていたとき、13行が
  「昇順」と報告されていた＝ゲートが嘘をついていた。
- **誤答だけに出る言い回しの検査の閾値は、期待値ではなく分散から決める。**
  正解42本・誤答168本では `MIN=10` を満たす4字が19種しかなく、的中率0.93 だと
  **偶然だけで平均0.83本鳴り、2回に1回赤くなる**（順列検定300回で実測）。`MIN=15` / `HIT=0.95`。
- **縦組みの傍線は「文字の右のアキ」に、1字ずつ引く。** 日本語の傍線は右。第1版はアキ 4.56pt。
  ★引き方は3つ試して1つだけが通る。`text-decoration` は右に出るが**改ページで文字の無い列に罫だけ残る**
  （第6回の左端に高さ6割の罫が1本立った）。`box-shadow: inset` は残らないが**文字ボックスの左内側**に出て
  字に食い込み、隣の列の波線と 0.4pt まで近づく。いま使っているのは
  `padding-right` で箱を右へ伸ばし、その右端に `box-shadow: inset` を引く形。
  `check.py <PDF> <PDF>` の `check_underlines` が、罫を実測して左右・アキ・宙に浮いた罫・
  **罫の長さに対して隣の字が足りない箇所**・**紙に墨が乗っているか**を見る。
- ★**`overflow: clip` で版面の外をまとめて切ってはいけない。** 縦組みでは1列目が版面の右端に接するので、
  その列の傍線（列の右のアキに出る）まで消える。**第6回 傍線部(Ｂ) の23字ぶんが丸ごと刷られていなかった**。
  改ページで取り残される影は、刷ったあとに `finalize()` が**左の余白だけ**から取り除く。
- ★**`get_drawings()` はクリップされたパスも返す。** 描画の命令を数えるだけでは
  「紙に出ていない罫」を1本も捕まえられない（実測: 正常な罫は墨43%前後、消えた罫は0%）。★罫は左辺と右辺の2本として出てくるので、
  墨を測る窓は罫の芯をまたぐように取る（片側だけだと右辺から測って12%しか出ず、しきい値との差が2%になる）。
  `ink()` が画素で確かめる。★**「隣に1字あれば合格」にもしない**。240ptの罫が1字で免責される。
- ★**`.u` の `padding-right` は 3.8pt が上限。** これを超えると1列目の罫が版面の外に出て刷られない。
  （第1版のアキは 4.56pt、いまは 3.42pt。ここは版面のめぐり合わせで決まるので、
  `check_underlines` が毎回アキを実測して 3.0〜6.5pt の範囲を見る。）
- ★**罫の拾い方は `rules_on_page` に一本化する。** 「横罫が何pt以上なら表の枠か」という
  当てずっぽうのしきい値は、傍線の箱が吐く上下辺（16.5pt）と本物の枠（22.5pt）の差が4pt も無く、
  1字幅の囲み（約15pt）を傍線と取り違える。
  ★このPDFの日本語は Type3 フォントなので `get_drawings()` に**字画もまぎれる**。
  罫だけを拾うのは「同じ x に隙間なく3つ以上積み上がり、太さぶんの対になっている」こと。
- **縦組みのブロック要素に `background` / `border-right` を付けるなら `display: inline-block` を忘れない。**
  縦組みでは `<p>` が段の全高を占めるので、レベル帯が 26pt×757pt の真っ黒なベタになり、
  巻頭の見出しの脇には 757pt の罫が立っていた（どちらも6ページぶん刷られていた）。
- **縦組みの段落は必ず `tcy()` に通す。** 素の文字列のままだと算用数字が90度倒れる
  （巻頭の説明段落だけがそうなっていた）。3桁以上の数字は縦中横にしない（桁のぶん横に潰れる）。
- **注番号 `(注N)` に `white-space: nowrap`。** 忘れると列をまたいで「(注」／「5)」と割れる
  （読み仮名 `.rb`・傍線末尾 `.ul`・解説編の `.nb` には入っていて、ここだけ抜けていた）。
  ★テキストを連結して照合する検査では、別の列に分かれていても同じ文字列に見えるので**絶対に出てこない**。
  `check.py::note_split` が4〜5字の x のばらつきで見る。
- **注は「（注）」の見出しごと1つのかたまりにする**（`.notes { break-inside: avoid }`）。
  割れると続きのページに見出しが無く、数字だけの列が本文のように見える。
- **注の見出し語には、本文が付けている読み仮名をそのまま添える**（第1版の流儀）。
  ★「見出し語の末尾に読み仮名が来る場合」だけを見ると、語の途中に付く形
  （「国の政(まつりごと)したため行ふ」「郡(こほり)の司(つかさ)」）が素通りする。
  また**読み仮名を外した形は必ず本文に見つかる**ので「本文にある形のどれか」でも通ってしまう。
- **縦組みの表で `text-align: right` を使わない。** 縦組みでは line-right＝列の下端なので、
  見出しの長い列で値の上に1cm以上の穴が開く。
- **設問の見出しに `break-after: avoid`。** 見出しだけが段の末尾に取り残される。
- **数行しか無い紙を作らない。** `orphans` / `widows` は 4。
- **底本を刷り物に出す**（`base`）。どの本を写したかが無いと異同を追えない。
- **解説が誤答を潰す順は番号順にそろえる。** 執筆順で書いたものを並べ替えるので、
  そのままでは42小問中40小問が番号順でなくなる（`make_sets.py::sort_kills`）。
- **誤答だけに出る言い回しを作らない。** 長さと位置の偏りだけでは足りない。
  実測で文末「〜である。」が誤答23本・正解0本、「てしまっ」「ものであ」「であって」も正解0本だった。
  `audit.py` が4字ごとの言い回しと文末を全数で数え、**その言い回しで切ったときの的中率が93%を超えたら**落とす。

## ファイル

```
src/        原稿（setN.py）・ルール表（rules.py）・正解位置表（positions.py）
sets/       刷る形（setN.json）。make_sets.py が生成する
sources/    原典の保存物（編集禁止）＋ emendations.json / cuts.json
out/        生成物（PDF・講師用メモ）。git 管理外
blind/      盲検証用（正解を伏せたもの）。git 管理外
```
