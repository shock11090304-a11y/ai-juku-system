## 設計

### 記号法は自前で作らない（パーサは共有・表示だけ読み替える）
分解 DSL（`{S:...}` / `( 副詞 )` / `[ 名詞 ]` / `< 形容詞 >`）は
**`scripts/eng_hinshi_bunkai/core.py` のパーサをそのまま読み込んで**使う（`core.py::_load_hb_core`）。

★ただし **紙に出すときの括弧だけ** 読み替える（塾長指示 2026-08-27・関正生『The Rules』式）。

| はたらき | DSL のソース | 紙の表示 |
|---|---|---|
| 副詞のカタマリ | `( )` | `( )` |
| **形容詞のカタマリ（関係詞節・分詞）** | `< >` | **`[ ]`** |
| 名詞のカタマリ | `[ ]` | `〈 〉` |

★読み替えの実体は **`scripts/eng_hinshi_bunkai/core.py::DISP_BR` の 1 か所だけ**。
パーサ（`render_analysis`）がそこで括弧を差し替えるので、
**この教材も品詞分解トレーニング教材も同じ記号で刷られる**。この教材は何も持たない。
記号を変えるときは必ずその 1 か所を触ること（片方だけ直すと生徒が 2 通りの記号を見る）。
`eng_hinshi_bunkai/check.py` に「古い記号名が解説の地の文に残っていないか」の検査を入れてある。

### かかり先（先行詞）を全部書く
形容詞のカタマリは**必ず名詞にかかる**のに、括るだけでは「どの名詞か」が伝わらない。
`REFS` に `(段落, 文) → [ (かかる先, カタマリの先頭, 種類) ]` を持ち、各文の下に
「`[ … ]` → その名詞」を全部書き出す。関係詞なら「先行詞」と表示する。慶應 43 / 東大 28 か所。
`check.py` が **①全部のカタマリに宣言があるか ②宣言がちょうど 1 つのカタマリを指すか
③かかる先が本当にそのカタマリより前に語として実在するか** を照合する。

### 本文は「印字そのまま」だけを持つ（単一ソース）
- `RAW` … 配布された過去問プリントの印字そのまま。空所は `[ 1 ]` `(B29)` `(C)` のまま。
- `FILLS` … 空所に入れる語。
- 解析に使う本文は **毎回 `RAW + FILLS` から作り直す**。埋めた本文は保存しない。

### 相互チェック 3 層（CLAUDE.md 2026-08-16）
| 層 | 実体 | 何を止めるか |
|---|---|---|
| ① 出力物どうしの照合 | `check_pdf.py` | 刷り上がりの PDF を読み直し、本文・全解析文・全和訳・全解答・全引用が紙にあるか。ビルドで落ちた・改ページで消えたを拾う |
| ② 機械検査 | `check.py` | 解析 DSL から復元した英文と本文の全文照合／4 セクションの有無／引用の実在／解答と本文の相互照合／(F) の語数とコンマ／宣言した文型と実際のラベルの整合／空所一覧表と本文の一致／**かかり先の網羅と前後関係**／**古い記号名の残留** |
| ③ 人手の再点検 | — | 正解の一意性（誤答が別解釈で正解にならないか）は機械では見えない。全問を敵対的に読み直す |

`check.py` は最後に **自己検査** を回す。データに変異を 16 種入れて
「全部落ちること」を確かめる。ゲートが無力化されていたらここで落ちる。

### 手で回す診断（ゲートではない）
`diag_pattern_count.py` … 「第3文型（SVO）×2」と書いたのに主節の V が 3 つある、という
**数え落とし**を洗い出す。強調構文・引用文の前置など<b>正当な不一致</b>が構造的に出るので、
ゲートにはしていない（例外表を持つと「例外に足して黙らせる」運用になって検査が死ぬ）。
出力を人が読んで判断する。ファイル名が `check*` に当たらないので `run_all_gates.py` は拾わない。

### 実際に捕まえた事故（2026-08-27）
- 解析 DSL の `{ }` の中に `< >` や `( )` を書いてしまい、**括弧が英文に漏れた** → ②で検出。
- 下線部の目印を `"will"` という短い文字列で指定していたため、**別の will に下線が付いた** → ①で検出。
  以後 `UNDERLINE` は `(ラベル, 本文で一意なアンカー, 下線を引く部分)` の 3 つ組にし、
  アンカーが本文に 1 回しか出てこないことを②が数える。
- 空所の印を消した跡の**二重スペース**でアンカーが当たらず、**下線が紙から消えた** → ①で検出。
  ビルドは置けなかった下線があれば例外で止まる。

### 解答・解説の敵対的再読で捕まえた誤り（2026-08-28・4 巡目）

### 記号の変更で捕まえた誤り（2026-08-27・3 巡目）
- `left her silence open to interpretation` の **to interpretation を形容詞のカタマリに入れていた**。
  かかる先が名詞ではなく形容詞 open なので誤り。副詞のカタマリ `( )` に直した。
  → かかり先を全部書かせる作業そのものが検査になった（名詞が見つからない＝分類が違う）。

  新しい `〈 〉` を知らなかった。`core.DISP_BR` から自動で拾うように直した。

## 表記の約束（プリント冒頭にも載せてある）
1. **受動態は見た目の形で数える**（能動に戻さない）。
2. **引用文はそれ自体を 1 文として分解する**。`said, "…"` と後ろに続くときだけ `[ ]` で
   said の O として示し、`"…," she said` と前に出ているときは独立させる。
3. `pat`（文型の見出し）には**主節の文型を全部**書き、従属節を添えるときは
   必ず「〜**節の中は**」で始める（`diag_pattern_count.py` がこの書き方を前提に数える）。

## 解説フォーマット
`server/main.py` の英語生成プロンプトが正典。
**🎯 コアイメージ → 🔬 文構造分析 → 📍 本文の根拠 → ❌ 誤答 NG 理由** の 4 セクション必須。
記述問題には誤答の選択肢が無いので、4 つ目は「よくある誤り」として同じ位置に置く。
`check.py` が 4 つ揃っているかを見る。

## 次に足すとき
1. `content_<key>.py` を作る（`META` / `RAW` / `FILLS` / `PARAS` / 必要なら `QUESTIONS`・`OPTIONS`・`ANSWER_MAP`・`UNDERLINE`）。
2. `check.py` の `ALL` と `load()` に key を足す。★足し忘れると引数なしで検査されない。
3. `build.py` の `main()` に `part_html()` を足す。
4. `check.py` → `build.py` → `check_pdf.py` の順に回す。
