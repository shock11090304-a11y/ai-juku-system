# 英文法ドリル補充 — 時制 / 接続詞 / 疑問詞・間接疑問 (90問)

「時制と接続詞、疑問の単元があまりない」という指摘への補充分。
既存プール (`grammar_drill_pool_v1.json`) はこの3単元が 32〜36 問で、
ドリル1本 25 問を2回配ると同じ問題が戻ってくる在庫だった。ここで各単元 +30 問する。

| 単元 (`GRAMMAR_UNITS` の名前) | 基礎 | 標準 | やや難 | 計 |
|---|---:|---:|---:|---:|
| 時制 | 8 | 12 | 10 | 30 |
| 接続詞 | 8 | 12 | 10 | 30 |
| 疑問詞・間接疑問 | 8 | 12 | 10 | 30 |

出題先は `grammar_questions` (CEO 画面の「📝 科目別 単元ドリル」が引くプール)。
入試問題そのものではなく**単元別ドリル**なので、1文1論点・自己完結の4択で書いてある。

## 塾長がやること (本番へ入れる)

CEO ダッシュボード → **📝 科目別 単元ドリル** → 緑の補充パネルの中の
**「🕰️ 時制・接続詞・疑問詞を補充 (90問・無課金)」** を押すだけ。

- 重複は自動スキップなので、二度押しても増えない (`dedup`)。
- 押したあと、単元「時制 / 接続詞 / 疑問詞・間接疑問」の在庫色が更新される。
  そのまま単元とレベルを選んで生徒に配信する。
- ★クラウドの Claude Code からは本番 API に繋げない (ネットワークポリシー)。
  投入は必ずこの画面から行う。

取り消したいとき (問題ごと引き上げる):

```sql
DELETE FROM grammar_questions WHERE source = 'drill-tense-conj-wh-20260909';
```

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `content.py` | **正典**。問題文・選択肢・正解 (文字列)・解説。ここだけを書き換える |
| `build.py` | 正典 → `seed-data/grammar_drill_pool_v2_jisei_setsuzoku_gimon.json` と `blind_view.json` |
| `_rules.py` | 「不良問題の定義」。build と check が**共有する唯一の判定** |
| `check.py` | 機械ゲート (`run_all_gates.py` / CI が回す) |
| `selftest_gate.py` | ゲート自体の変異試験。わざと壊して、必ず指摘されることを確かめる |

直したいときは `content.py` を直して:

```
python3 scripts/eng_drill_jisei_setsuzoku_gimon/build.py     # 再生成
python3 scripts/eng_drill_jisei_setsuzoku_gimon/check.py     # 検査
python3 scripts/eng_drill_jisei_setsuzoku_gimon/selftest_gate.py
```

★**seed JSON を手で直さない**。直すと build.py の検査を素通りできてしまうので、
`check.py` が「再生成して差分ゼロ」を機械で確認して落とす。

## 設計の約束 (壊すと同じ事故が戻る)

- **正解を番号で書かない**。`content.py` は正解を*文字列*で持ち、位置は build が
  (単元, レベル) ごとに 0→1→2→3 のラウンドロビンで割り当てる。
  手で番号を振ると必ず偏る (2026-08-02 の指摘) し、選択肢を1つ差し替えた時にずれる。
- **解説は値参照**。「①が正解」「2番目」と書かない。位置は振り直されるので嘘になる。
  正解の語句をそのまま書き、誤答が誤りである理由も書く。
- **迷う組み合わせを選択肢に同居させない**。`will` と `be going to`、`who` と `whoever` のように
  文脈次第で両方成り立つ組は、片方を選択肢から外す。正解が2つある問題は機械では見えない。
- **判定を書き写さない**。単元名は `server/main.py` の `GRAMMAR_UNITS` から読む。
  判定は `_rules.py` の一本道。build と check に同じ条件を2度書くと、片方だけ直されてずれる。

## 相互チェック (単一経路の生成物を信じない)

1. **出力どうしの照合** — 正典 `content.py` の正解*文字列*と、出力 JSON の `answer` (番号) が
   指す選択肢を突き合わせる。番号の振り直しでずれたら落ちる。
2. **機械検査** — `check.py` (取込契約・正解の一意性・値参照・正解位置・seed-data 全体での重複・
   CEO ボタンの導線) + `scripts/seed_survey.py` (seed-data 全体の物差し) 。
   さらに `selftest_gate.py` が**ゲート自身**を 21 種の変異で試す。
   実際にこの変異試験で、書いたばかりのガードの穴が 2 つ見つかっている
   (「解説が誤答に触れているか」を素朴な部分一致で数えると、正解 `have known` の中の `know` を
   誤答への言及と誤認して素通りする / 逆に正解を伏せ字に置換すると `Who` を伏せた時点で
   `Whom` `Whose` まで壊れて誤検出になる。出現位置の包含関係で数えるのが唯一正しい)。
3. **人手の再点検** — 正解の一意性は機械では見えない。`blind_view.json` (正解・解説を落とした
   盲解き用ビュー) を独立に解き直して、キーと突き合わせる。
   ★盲解きをする人 (や別セッション) に `content.py` / seed JSON を見せないこと。見せた時点で
   独立でなくなり、この層は「確認したつもり」になる。

### 2026-09-09 の盲解きで実際に見つかった不良 (8問を差し替え・修正)

独立した2名が `blind_view.json` だけを見て解き、**第一選択は90問すべてキーと一致**した。
価値があったのは一致そのものではなく、「もう一方の選択肢でも成立する」という指摘のほう:

| 問 | 何が起きていたか | 直し方 |
|---|---|---|
| 時制 basic | `every evening` だけでは現在形に決まらない (`did` = 過去の習慣でも成立) | 「今も担当だ」と現在の手がかりを本文に足した |
| 時制 basic | `when the doorbell rang` に `took` を入れると「鳴ってから浴びた」で成立 | 「すぐ出られなかった」を足して進行中に固定 |
| 時制 standard | 台風が過去のものなら `reached` も自然 | `approaching` と `tomorrow` で未来に固定 |
| 時制 standard | `It was the first time I saw …` はくだけた言い方で実在 | 争点の `saw` を選択肢から外した |
| 時制 standard | 歴史的事実でも報告動詞の後の `had taken` は非文ではない | 争点を外し、時制の一致の誤り `would take` を誤答に据えた |
| 時制 advanced | `by noon` があると `would have sent` が「未来完了の時制の一致」で成立 | 期限を外した → **2巡目で別の欠陥**: promise は「〜したと断言する」でも使えるので `had sent`(すぐ送ったと言い張った) も成立していた。送る時点を `the following morning` と約束より後ろに固定して閉じた |
| 接続詞 standard | `for` の問題に `so` が同居し、原因→結果で普通に読める | `so that` に差し替え → **2巡目**: 結果の so that も文法的には読めると指摘され、どの読み方でも成立しない `in case` に再差し替え |
| 接続詞 standard | `The reason … is because` は規範では誤りだが実際には広く使われる | 自動採点で断じるには弱いので `even if / even though` の問に差し替えた |

差し替えた8問は**現在の形で改めて別の1名に盲解きさせた**。そこで上の2巡目の欠陥が出た
(=「直したつもり」で終えていたら、2問が二重正解のまま本番に入っていた)。
残る既知の薄さも記録しておく: 「It was the first time I **have seen** …」は規範では誤りだが
くだけた話し言葉では実在する。入試の物差しでは `had seen` が正解で、この誤答こそ狙って外させたい形なので
そのまま残している。

直した2問には、**同じ穴を開け直さないための注意書きを `content.py` の該当箇所に置いてある**
(「the following morning を by the following morning に整えない」「この問の誤答に because/since/as/so を
置かない」)。直す人が見るのは README ではなく問題の隣なので、そこに書く。

★教訓は**「誤答は文法的に誤りであるだけでなく、どの読み方でも成立しないこと」**。
`will` と `be going to`、`so` と `for` のように、文脈次第で両方成り立つ組を同居させない。
機械ゲートはこれを見つけられない (どちらも4択として整っているため)。差し替えた8問は、
現在の形で改めて第三者に盲解きさせて確認している。

**付加疑問 (`Open the window, will you?`) と否定疑問への応答を「疑問詞・間接疑問」に入れているのは
意図的**。`GRAMMAR_UNITS` に疑問文の単元はこれしかなく、既存プール v1 も同じ扱いをしている
(「You are a student, (   )?」等)。プールごとの慣行に合わせる、という約束に従っている。
