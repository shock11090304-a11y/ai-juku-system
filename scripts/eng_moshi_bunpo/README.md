# 高3 記述模試対策 英文法・語法 実戦問題集

高3の夏〜秋に受ける記述模試（河合塾 全統記述模試／駿台全国模試 など）に向けた文法・語法の演習書。
**模試1回分の再現ではなく、記述模試で実際に使われる三つの形式だけを集めた**演習書。

- 四択（空所補充）10問 ＋ 語句整序 5問 ＋ 誤り指摘 5問 ＝ 1回20問・100点・25分
- 全3回（第1回 標準／第2回 標準〜やや難＝第1回と同じ帯／第3回 上位）＝ 60問

★**難度は一直線に上がらない**。2026-08-18 に、延べ182体のエージェントで全60問を検証した結果、
第2回20問のうち14問が第1回と同帯以下だった。第1回・第2回は同じ帯を2周する回、
第3回だけが一段上がる回、というのが実態。標榜をこれに合わせてある
（当初は第2回=「正答率が下がる帯」／第3回=「駿台全国模試と同程度」と書いていたが、
実物は GMARCH・地方国公立の帯で、駿台全国には一段足りなかった）。
**難度を実際に上げるなら、第2回の下位14問と第3回の易しい問の差し替えが要る**（未実施）。

## 使い方

機械（組版・ゲート・盲検証）は姉妹編と共有し、**データだけがここにある**。

```bash
WORKBOOK_DIR=scripts/eng_moshi_bunpo python3 scripts/eng_kokkoritsu_nankan/check.py
WORKBOOK_DIR=scripts/eng_moshi_bunpo python3 scripts/eng_kokkoritsu_nankan/build.py
```

`build.py` は先に `check.py` を呼び、FAIL があれば 1バイトも書かずに落ちる。
出力は `~/Desktop/koushou3_kijutsu_moshi_bunpo_{問題編,解答解説編}.pdf`
（日本語ファイル名は NFD/NFC 不一致で FileNotFound を起こすので、英数字で書いてから `mv`）。

引数なしの `check.py` は `BOOKS` に登録された全冊を1冊1プロセスで検査する。
本書は `eng_moshi_bunpo: 60` として登録済み（**登録しないと黙って無検査になる**）。

## ★このデータ形式で踏んだ罠

- **誤り指摘の正解位置は機械で散らせない**。`parts[0..3]` は stem の `{a}`〜`{d}` に差し込む
  **位置そのもの**なので、四択と同じ要領で並べ替えると英文が別の語順に組み替わって崩壊する
  （実際に `this model to to be superior is said` という文が出た。check.py の
  「訂正後の英文が壊れている」ゲートが検出）。誤りの位置は**作問時に手で散らし**、
  分布ゲートで担保する。四択（`_balance_mc()`）だけが機械で散らせる。
- **集合名詞の複数扱いを誤りにしない**。`the staff have rearranged` は英では正用なので
  誤り指摘の題材にできない。用法が英米で割れるものは避ける。
- ★**姉妹編とほぼ同文の設問を作らない**。ゲートは本をまたいで見ないので機械では一切捕まらない。
  実測で**6組**出た（`Had it not been for〜` は3冊に同じ問／分詞構文と使役は選択肢4つが完全一致）。
  同じ生徒が中堅編→難関編→本書と解くので、**新しい本を書いたら姉妹編の content と突き合わせる**。
  → 2026-08-18 に `check.py` の **G21**（▶ポイントを本またぎで類似度照合）を新設して機械化した。
  導入直後に4件を検出し、計7問を差し替えて**本書の警告はゼロ**にした。
  ★ただし姉妹編2冊（難関編・中堅編）には各9件の WARN が残っている（2026-08-18 実測）。
  とくに `Had it not been for his help` は両書で tokens・ans・exp がほぼ同一の同一問で未対応。
  「既知ノイズ」として全部素通りしないよう、件数を実測で書いておく。
- **「誤りが1つも無い誤り指摘問題」を作り込んだ**（2回）。①仮定法の `If S had done` を誤りのつもりで
  置いたが、その文はそのまま正しい英文だった。②`helped us carrying our luggage` は
  **分詞構文としても読めて誤りが消える**（「荷物を運びながら手伝った」）。
  → 作ったら**訂正前の全文が本当に非文か**、**別の構文としても読めないか**を確かめる。
- **整序の答えに小文字の `i` を残すと、解答編に誤った英語が刷られる**。指示文の
  「文頭に来るべき語も小文字で示してある」は**文頭語だけの約束**で、文中の I には適用されない。
- **前書き・部扉の地の文は `S["intro"]`（CJK 折り返し）で組む**。効かせないと行頭に「。」が落ちる。
  ★`S["note"]` 自体に CJK を効かせてはいけない。note は**表のセルにも使われ**、
  中学英語の本の活用表のように英単語が入るセルで単語が途中から割れる。
- ★**KeepTogether で括るときは、元の append を消す**。構成表を括ったとき見出しと導入文を
  KeepTogether の中に書き足しただけで元の append を残したため、**同じ2行が2ページに二度刷られた**
  （`_pdf_qa.py` の「同一文字列の二重印字」はページ内しか見ないので素通りした）。
- **解答編の「完成文」は文頭を大文字に戻す**。問題編は「文頭に来るべき語も小文字で示す」約束なので
  `ans` は小文字始まりだが、そのまま刷ると `no matter what happens, we will …` という
  誤った英語を模範解答として載せることになる（`completed_sentence()` で復元）。
- **表紙が中身に無いものを名乗らないようにする**。解答編の表紙は「採点のポイントつき」固定だったが、
  採点要素（英文和訳・和文英訳）を持たない本ではその形式が存在しない。
  ★判定は `ELEMENT_KINDS` の**宣言**でなく**実際の設問数**で行う（宣言はどの本も同じ値が書いてある）。
- ★**共有スタイルに手を入れると、別の本が黙って壊れる**。`S["partsub"]` に CJK 折り返しを
  足したら、同じスタイルを使う**解答編の部見出しで「100点／満点」が割れた**（中堅編の退行）。
  → 用途ごとにスタイルを分ける（`S["aim"]`）。**共有機械を触ったら6冊を再ビルドして差分を見る**。
- **区切りの単位語は本ごとに持たせる**（`BOOK["unit"]`、既定は "部"）。
  模試形式の本でデータが「第1回」なのに機械が「第1部」と刷ると、
  紙面が「第1部 第1回 標準レベル」と二重表記になる。表紙の「各部」と前書きの「各回」も食い違う。
- **`_balance_mc()` の起点は大問ごとにずらす**（`(rank + p["no"] + s["no"]) % 4`）。
  0 起点固定だと 10問の大問は必ず 1番3/2番3/3番2/4番2 になり、冊子全体でも同じ偏りが積み上がる
  （実測 9/9/6/6 → 8/7/7/8）。
- ★**ゲートが「検査済み」と名乗る範囲を実態に合わせる**。別解ゲートの初版は、日本語の但し書き
  （「または〜」「〜の語順も可」）まで検査したことにして緑を出していた。機械で見られないものは
  「未検査N件（要目視）」と印字する。★**注記の言い回しは本ごとに違う**
  （「文頭に来るべき語」／「文の最初に来る語」）ので、片方だけを探すと正しい本を落とす。

- ★★**データを書き戻したのにゲートが古い内容を見続けることがある**（2026-08-18 に踏んだ）。
  macOS のシステム Python は `__pycache__` ではなく
  `~/Library/Caches/com.apple.python/<絶対パス>/` にバイトコードを置く。
  **1文字だけ直す（サイズ不変）＋同じ秒に書き戻す**と、Python が pyc を有効と誤判定して
  **直す前のデータで検査する**。`python3 -B` は書き込みを止めるだけで読み込みは止まらないので効かない。
  ★症状: ソースを grep すると直っているのに、ゲートだけが古い値で FAIL/PASS する。
  → 疑ったら消す:

```bash
python3 -c "import importlib.util,os; p=importlib.util.cache_from_source('scripts/eng_moshi_bunpo/content_p2.py'); os.path.exists(p) and os.remove(p)"
```

- ★★**整序の「2通り成立」は5種類の原因で起きる**（1問を5回作り直して全部踏んだ）。
  作問時にこの順で潰す:
  1. **副詞の位置**が自由（`without first consulting anyone` ⇔ `without consulting anyone first`）
     → 位置が動く副詞（first / even / never）を語群に入れない。
  2. **句動詞が分離できる**（`turn down the offer` ⇔ `turn the offer down`）
     → 分離しない一語の他動詞にする（turn down → reject）。
  3. **前置詞句が副詞句としても読める**（`in the field` が「その分野の」とも「現場で」とも）
     → 副詞句に読めない後置修飾にする（`of the committee`）。
  4. ★**修飾句が主語側に付きうるときは、動詞を枠の外に固定する**
     （`The document [took the experts in the field …]` ⇔ `The document in the field took …`）
     → **動詞は枠の外に固定する**（`The document took [ … ]`）。これがいちばん効く。
  5. **目的語が枠外に固定されていないと副詞句を前に出せる**
     → 受け皿の語（anyone 等）は frame 側に置く。
  ★機械ゲートは「トークンと解答の語が一致するか」しか見ない。**2通り成立は盲ソルバーにしか出せない**
  ので、整序を作り直したら必ず「一意性だけを見る」役を立てて解かせ直すこと。

- ★**解説に作者メモを書くと、そのまま解答編に刷られる**。`★reject は turn down と違い…`
  `この frame には嵌まらない` を実際に印字していた（姉妹編5冊には1件も無い＝差し替え時に混入）。
  → `check.py` の **G22** が `exp` / `point` / `fix` と**前書き・扉・指示文**を走査する。
  ★判定は「日本語の文の中で frame / tokens / stem / parts が使われている」形に絞ること。
  部分文字列で見ると `the school system` → stem、`framework` → frame を誤検出し、
  クォート付きだけで見ると「frame の [ ] を見よ」を取り逃す（両方実測した）。
- ★**正解番号の「3連続」は分布ゲートでは捕まらない**。実測で3冊とも `①①①` を持ち、
  古文助動詞は `①①①①` の4連続だった。分布が均等でも、1問当てると次も同じ番号だと
  思わせる誘導になる。→ `_workbook_gates.break_answer_runs()` を content から呼んで
  データ側で潰し、`check.py` の **G24** が3連続を FAIL にする。
  ★連続の解消は「番号の違う問と**交換**」なので分布は不変。解説が選択肢番号を参照していないことが前提。
- ★**「誤りが1つも無い誤り指摘」をまた作った**（3回目）。`The library renovated last spring
  offers …` は後置修飾の過去分詞として完全に正しく、誤りがどこにも無かった。
  機械ゲートは「fix の左辺が下線部に実在するか」までしか見ないので、**訂正前が本当に非文かは
  盲ソルバーにしか出せない**。差し替えたら必ず1問だけでも解かせ直すこと。

## 検証（この順で）

1. **機械ゲート**（対象6冊を1冊1プロセスで）

```bash
python3 scripts/eng_kokkoritsu_nankan/check.py
```

2. **盲検証** — 正解を伏せて3人の独立ソルバーが解き、Python が厳密照合する。
   視点は A=唯一解／B=第2正解探し／C=英文の自然さ・出題成立性。
   ★モデルを分散させる（A=Sonnet、B・C=Opus）。同じモデル3人だと同じ盲点で揃って間違える。

```bash
WORKBOOK_DIR=scripts/eng_moshi_bunpo python3 scripts/eng_kokkoritsu_nankan/blind.py make <出力先>
WORKBOOK_DIR=scripts/eng_moshi_bunpo python3 scripts/eng_kokkoritsu_nankan/blind.py reconcile <出力先>
```

3. 解説の事実性レビュー・冊子レビューを並列で。
   ★**設問を差し替えたら、その設問だけ盲検証をやり直す**（差し替えが新しい穴を作る）。
4. **PDF の機械 QA** → 代表2〜3ページだけ目視（★全ページを画像で Read しない）。

```bash
python3 scripts/_pdf_qa.py ~/Desktop/高3記述模試対策_英文法語法_実戦問題集_問題編.pdf
```

★`_pdf_qa.py` は本書の回扉のうち **p4 だけ**を「ほぼ空白のページ」として ✗ にする。
   扉は設計どおりなので p4 は既知の例外。**それ以外のページ番号が出たら本物**。
   ★判定は「本文200字未満」なので、**扉の説明文（`aim`）を削ると他の扉も ✗ に転ぶ**。
   ✗ が出たら必ずそのページを開いて中身を見ること（数値は版で動くのでここには書かない）。
