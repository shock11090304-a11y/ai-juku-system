# 英検準1級 単語テスト（4択・全10回×20語＝200語）

塾で配って書かせる用の**単語テスト**。1回＝A4 1枚。生徒は意味を4択で選び、番号を解答欄に書く。
解答解説編は**別冊**（指導者が保管）なので、問題編を渡しても答えは漏れない。

```
content.py       単一ソース。200語の (word, pos, gloss, distractors, usage_en, usage_ja, note)
build.py         content.py → 問題編/解答解説編 HTML → Chrome print-to-pdf → ~/Desktop
check.py         機械ゲート（build.py が呼ぶ。FAIL が1つでもあれば HTML を書き出さない）
make_blind.py    正解を伏せた blind.json ＋ 照合用 answer_key.json
reconcile.py     盲ソルバーの解答と鍵を Python で決定的に照合
```

```bash
python3 build.py --pdf      # ゲート → HTML → PDF（~/Desktop に2冊）
python3 make_blind.py       # 盲検証用データ
python3 reconcile.py solver_A.json solver_B.json
```

## 設計の勘所（ここを踏み外すと教材として壊れる）

### 1. 正解位置は md5 で振る。連番で振ると「読まずに全問正解」できる
`build.assign()` が `md5(salt + word)` 順に 0,1,2,3… と振るので各回ちょうど5問ずつ。
連番だと分布は均等でも正解列が完全周期になり、英単語を1つも読まずに満点が取れる。
同じ位置が4連続すると生徒が自分の答えを疑うので、salt を回してそれも避けている。

### 2. ★★「正解肢だけ書式が違う」を3回続けて踏んだ（`build.brief()`）

この教材で最も大きかった欠陥。**正解肢だけが `content.py` の語義欄から機械生成され、
誤答肢だけが手書き**なので、表記の流儀がそろわない。潰すたびに次の目印が現れた。

| 世代 | 目印 | 実測 | 対処 |
|---|---|---|---|
| 初版 | 正解肢だけが長い | 単独最長 **157/200 (78%)** | 語義を最初の「、」で切る |
| 2版 | 正解肢だけに丸カッコ | **39/39 (100%)**＝19.5%が確定 | カッコ記号を落とす＋誤答にも限定句を付ける |
| 3版 | 正解肢だけに中黒「・」 | **11/16 (69%)** | 印字面では「や」に開く |
| 4版 | 誤答にだけ限定句を盛った反動で**正解が最短**に | 「最短を選ぶ」**34.5%**（第6回は51.5%） | 誤答54語を簡潔に書き直す |
| 5版 | 今度は正解が**2番目に短い**に寄る | 「2番目に短い」**33.6%** | 12問の長さを微調整して順位分布を平らに |

最終: 長さ順位ごとの得点 25.1 / 27.8 / 25.6 / 21.5 %（ランダム＝25%）。

**教訓その1**: 記号を1つずつ潰すのは追いかけっこになる。根本原因は
「正解肢は機械生成・誤答肢は手書き」という**出どころの非対称**なので、
誤答肢の側にも同じ具体性（限定句）を持たせるところまでやって初めて止まる。
`check.py` **G12** が記号ごとに正解との相関を数え続ける。

**教訓その2 ★**: 「単独最長／単独最短の件数」で測ると足りない。**同点を 1/n で按分した
“戦略の期待得点”**で測ること。4版のとき単独最短は 21% で基準内なのに、同点を拾う分で
実際の得点は 34.5% あった。**G5 は件数ではなく期待得点を見る実装に作り直してある**。
さらに 1つの順位だけ見ても足りない（最短を潰したら2番目に立った）ので、
**4順位すべての得点を出して平らかどうかを見る**。

### 3. ★印字する選択肢は「主要語義1つ」に切る（`build.brief()`）
初版は正解だけが「〜を和らげる、**軽減する**」のように長く、誤答は「〜を挑発する」と短かった。
実測で **正解肢が単独最長の問題が 200問中157問（78%）**。
一番長い選択肢を選ぶだけで78点取れる状態だった。
`brief()` が全4肢に同じ規則（最初の「、」で切る）を機械的に適用して 22% に是正した。
第2語義は解答解説編の「意味」欄に残るので情報は失われない。
「／」で区切った別系統の2義（sanction＝制裁／認可）は切らない。

### 3. 同じ紙の上で正解が衝突していないか（G6）
4択の語彙テスト特有の事故。ゲートが実際に検出したもの:
- 第1回 alleviate の誤答「〜を悪化させる」が、**同じ紙の exacerbate の正解と完全一致**していた。
- 第3回 inhibit と curb が**どちらも「〜を抑制する」**になり、正解が2つあるように見えていた。
- 第3回 foster の誤答「〜を妨げる」が、**同じ紙の hamper の正解**だった。
いずれも「1問だけ見れば正しい」ので盲ソルバーでは構造的に検出できない。Python で紙単位に走査する。

### 4. 誤答が正解の別語義になっていないか（G4）
`cores()` が日本語語義から意味の核（漢字2字以上／カタカナ2字以上）を抜いて突き合わせる。
- 接尾の 的/化/性/さ/み は落として比較する（「深刻化」と「深刻」を同一視するため）。
- 部分文字列では照合しない。「暫定的」と「決定的」が “定的” で衝突する誤検出が出た。
- 意味が正反対で良い誤答になるもの（phase out ⇔ 段階的に導入する＝phase in）は
  `ALLOW_CORE_SHARE` に**理由つきで**例外登録する。理由を書けないものは例外にしない。

### 5. 熟語パートは易化しやすい
準1級 対策問題集で実際に指摘された事故（put off / carry out / keep up with が2級級）。
`TOO_EASY_IDIOM` で中学〜2級の句動詞を禁止し、各回ちょうど4つ入っているかも数える。

### 6. 用例に見出し語が実在するか（G8）
`usage_en` に見出し語の語幹が含まれることを機械照合する。
不規則変化（wear off → wore off、fall through → fell through）は `USAGE_IRREGULAR` に
理由つきで登録。ここを緩めると「用例が別の語の例文」という事故が通る。

### 7. 解答解説編は各回の実施後に配る前提 → メモの「先出し」が漏洩になる（G13）
第1回 deter のメモに「名 deterrent」と書くと、deterrent は第8回の見出し語なので
その回は必ず正解される。同型で deficit の「⇔ surplus」（surplus は第5回）、
sanction の用例 `impose economic sanctions`（impose は第9回）も検出。
**盲ソルバーは1問しか見ないので構造的に検出できない**。Python で全メモ・用例を
「後の回の見出し語」に対して走査する。

### 8. 表紙の数字はデータから数える（`build.stats()`）
過去の問題集で「表紙に112問と刷って実際は103問」という事故がある
（**3人の盲ソルバー全員が素通り＝解く人は表紙を見ない**）。
回数・問数・単語/熟語の内訳・満点・目標点はすべて `stats()` が実データから生成する。

### 9. 印刷物に「実測していない事実」を書かない
初版は各回に「最頻出①」「頻出②」「差がつく③」という頻度ラベルを付けていたが、
語彙リストと突き合わせたところ**「最頻出」の回のほうが実際には難しい**（第1回の平均頻度順位
1722 に対し第5回1153）と分かった。裏の取れない主張は配布物から外し、テーマ表示のみにした。

## 検証の層（どれか1つでも省くと必ず漏れる）
1. `check.py` の機械ゲート G1〜G10（何度でも回せる。AIレビュー1本より安い）
2. `scripts/_pdf_qa.py` — グリフ監査＋ページ別文字数（空白ページ・はみ出し検出）
3. 独立レビュー3系統（報告の**前**に回す。最終確認ではない）
   - 盲ソルバー2名（唯一解の確認 / 第2正解探し）→ `reconcile.py` が Python で照合
   - 語義・用例・note の事実確認とレベル妥当性（WebSearch で一次情報に当たる）
   - 冊子横断の不備（解答漏洩・表紙の数字・解答一覧の一致）

### ★具体物ダミーは1問1本まで（G17）
正解の語義は抽象・改まった語なので、**物理的な具体物を指す肢は構造的に必ず誤答になる**。
実測で35本すべて誤答。1問に2〜3本入ると「具体物を消す」だけで実質2択・0択になり、
`water down`（水をやる／洗い流す／水中に沈める）と `testimony`（遺言／身分証明書／遺言の執行人）は
**誤答3本とも具体物＝答えが確定**していた。綴り混同を狙うダミー
（deterrent/detergent、peril/pearl、mundane/Monday…）は教材として価値があるので全廃せず、
**1問1本に制限**して差し替えた（35本→26本・26問）。

### ★どこで止めたか（残っている tell を隠さない）
最後の抜け道スキャンで、**日本語の選択肢だけを使った文字n-gramベイズ分類器が
交差検証で 39.9%**（ランダム25%）を出した。原因は「正解＝この単語帳のテーマ語彙
（損な・抑制・格差・影響・低迷）／誤答＝日常語（修復・試験・治療・居住・吸収）」という
**レジスタの差**。これは**直さないと決めた**。理由:
- 学生が紙の上で使える手ではない（160問で学習して40問を当てる分類器が必要）。
- 手作りルールは58本すべて28%以下（帰無最大34.9%の範囲内）＝**人間が使える抜け道は残っていない**。
- C1語の正しい訳語は本質的に抽象語なので、これを消すには誤答も全部抽象語にする必要があり、
  誤答の妥当性（＝紛らわしさ）を犠牲にする。教材としては逆効果。

同様に残す判断をしたもの: 具体物ダミー26問（1本まで＝消せても3択どまり・+1.1%）、
反意ペアが見える23問（+2.9%）。いずれも「知っていれば消せる」＝語彙力の一部でもある。
**合格条件は「人間が使える戦略が30%を超えないこと」**であって、機械学習器を
偶然水準まで落とすことではない、と定義して打ち切った。

### ★見出し語を1文字でも変えると正解位置が動く
`assign()` は `md5(salt + word)` 順に位置を振るので、`on par with` → `on a par with` の
ような**綴りの修正だけでその回の正解位置が入れ替わる**。実際に第10回で4問ずれ、
盲ソルバー4名が全員そろって鍵と違う答えを返した（＝一見「鍵誤り」に見える）。

**この見分け方が要点**: 全員が一致して外すのは、鍵誤りか**位置の移動**のどちらか。
`旧配列でソルバーが選んだ文字列` と `新配列の正解文字列` を突き合わせれば
Python で確定できる。同一なら位置が動いただけで解答内容は正しく、盲検証をやり直す必要はない。
（今回は4問とも同一で、200問すべて内容一致を維持した。）

### ★機械ゲートにできなかったもの
「印字語義と用例訳が別の語義になっている」型（induce の語義順を入れ替えたら用例
`induce sleep（眠気を誘う）` が取り残された）は**ゲートにできなかった**。
`cores()` は漢字2字以上しか核にしないので「〜を罰する／違反者を罰する」のような
完全に対応した組まで「核が無い」と誤検出し、実装すると73件中ほぼ全部が誤報になる。
**本物の警告が埋もれてゲート全体が信用されなくなるので、入れずに外した。**
この型は辞書照合レビュー層で拾う。★語義の順序を入れ替えたら用例を必ず読み直すこと。

★盲ソルバーには**番号の起点を必ず明示する**（1始まり）。このリポジトリで 0/1 始まりの
取り違えにより「四択が全問ずれて鍵誤りに見える」事故が再発している。`blind.json` の
`answer_format` にその旨を書いてある。

## レベルの実測（2026-08-04・一次情報で裏取り済み）
Oxford 公式 *The Oxford 3000/5000 by CEFR level* と全160単語を照合した結果:
- **A1〜B1（＝2級以下）の語は0件**。最低でも B2。内訳は B2:16 / C1:61 / Oxford5000圏外:83。
- 一方で、3,000語規模の準1級リスト（パス単準1級・でる順）に無く1級側リストにある語が **48/200＝24%**。
  ただし準1級の目標語彙は7,500〜9,000語で参照リストは3,000語規模なので「リスト外＝1級」とは言えない。
  **「準1級の上位〜1級の下位に寄っている」**と読むのが妥当。

★`check.py` の `TOO_EASY_IDIOM` は**熟語の易化しか見ていない**。
単語側のレベル上限を機械で見る仕組みは無い（機械可読なCEFR表を持っていないため）。
語を足すときは Oxford CEFR リストに手で当てること。
