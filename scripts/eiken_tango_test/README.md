# 英検準1級 単語テスト（4択・全20回×20語＝400語）

塾で配って書かせる用の**単語テスト**。1回＝A4 1枚。生徒は意味を4択で選び、番号を解答欄に書く。
解答解説編は**別冊**（指導者が保管）なので、問題編を渡しても答えは漏れない。

- **第1〜10回**（200語）… 準1級の上位〜1級の下位に寄った帯。24%が準1級3,000語リスト外。
- **第11〜20回**（200語）… 上が取りこぼしていた**準1級の中核**を埋める帯。テーマ別。

```
content.py       単一ソース。400語の (word, pos, gloss, distractors, usage_en, usage_ja, note)
build.py         content.py → 問題編/解答解説編 HTML → Chrome print-to-pdf → ~/Desktop
check.py         機械ゲート（build.py が呼ぶ。FAIL が1つでもあれば HTML を書き出さない）
make_blind.py    正解を伏せた blind.json ＋ 照合用 answer_key.json
reconcile.py     盲ソルバーの解答と鍵を Python で決定的に照合
```

```bash
python3 build.py --pdf      # ゲート → HTML → PDF（~/Desktop に2冊）
python3 make_blind.py       # 盲検証用データ
python3 reconcile.py <盲ソルバーの解答>.json ...   # 解答ファイルはコミットしない（版が変わると照合できなくなる）
```

## 設計の勘所（ここを踏み外すと教材として壊れる）

### 1. 正解位置は md5 で振る。連番で振ると「読まずに全問正解」できる
`build.assign()` が `md5(salt + word)` 順に 0,1,2,3… と振るので各回ちょうど5問ずつ。
連番だと分布は均等でも正解列が完全周期になり、英単語を1つも読まずに満点が取れる。
同じ位置が4連続すると生徒が自分の答えを疑うので、salt を回してそれも避けている。

### 2. ★★「正解肢だけ書式が違う」を3回続けて踏んだ（`build.brief()`）

この教材で最も大きかった欠陥。**正解肢だけが `content.py` の語義欄から機械生成され、
誤答肢だけが手書き**なので、表記の流儀がそろわない。潰すたびに次の目印が現れた。

| 世代 | 目印 | 実測 | 対処 |
|---|---|---|---|
| 初版 | 正解肢だけが長い | 単独最長 **157/200 (78%)** | 語義を最初の「、」で切る |
| 2版 | 正解肢だけに丸カッコ | **39/39 (100%)**＝19.5%が確定 | カッコ記号を落とす＋誤答にも限定句を付ける |
| 3版 | 正解肢だけに中黒「・」 | **11/16 (69%)** | 印字面では「や」に開く |
| 4版 | 誤答にだけ限定句を盛った反動で**正解が最短**に | 「最短を選ぶ」**34.5%**（第6回は51.5%） | 誤答54語を簡潔に書き直す |
| 5版 | 今度は正解が**2番目に短い**に寄る | 「2番目に短い」**33.6%** | 12問の長さを微調整して順位分布を平らに |

最終（全400問）: 長さ順位ごとの得点 **24.3 / 27.4 / 25.6 / 22.8 %**（ランダム＝25%）。
★この数字はデータを1語でも触ると動く。README に写した値は古くなる——**判断は必ず `python3 check.py` の出力で行うこと**（上限も実データから計算される）。

**教訓その1**: 記号を1つずつ潰すのは追いかけっこになる。根本原因は
「正解肢は機械生成・誤答肢は手書き」という**出どころの非対称**なので、
誤答肢の側にも同じ具体性（限定句）を持たせるところまでやって初めて止まる。
`check.py` **G12** が記号ごとに正解との相関を数え続ける。

**教訓その2 ★**: 「単独最長／単独最短の件数」で測ると足りない。**同点を 1/n で按分した
“戦略の期待得点”**で測ること。4版のとき単独最短は 21% で基準内なのに、同点を拾う分で
実際の得点は 34.5% あった。**G5 は件数ではなく期待得点を見る実装に作り直してある**。
さらに 1つの順位だけ見ても足りない（最短を潰したら2番目に立った）ので、
**4順位すべての得点を出して平らかどうかを見る**。

### 3. ★印字する選択肢は「主要語義1つ」に切る（`build.brief()`）
初版は正解だけが「〜を和らげる、**軽減する**」のように長く、誤答は「〜を挑発する」と短かった。
実測で **正解肢が単独最長の問題が 200問中157問（78%）**。
一番長い選択肢を選ぶだけで78点取れる状態だった。
`brief()` が全4肢に同じ規則（最初の「、」で切る）を機械的に適用して 22% に是正した。
第2語義は解答解説編の「意味」欄に残るので情報は失われない。
「／」で区切った別系統の2義（sanction＝制裁／認可）は切らない。

### 3. 同じ紙の上で正解が衝突していないか（G6）
4択の語彙テスト特有の事故。ゲートが実際に検出したもの:
- 第1回 alleviate の誤答「〜を悪化させる」が、**同じ紙の exacerbate の正解と完全一致**していた。
- 第3回 inhibit と curb が**どちらも「〜を抑制する」**になり、正解が2つあるように見えていた。
- 第3回 foster の誤答「〜を妨げる」が、**同じ紙の hamper の正解**だった。
いずれも「1問だけ見れば正しい」ので盲ソルバーでは構造的に検出できない。Python で紙単位に走査する。

### 4. 誤答が正解の別語義になっていないか（G4）
`cores()` が日本語語義から意味の核（漢字2字以上／カタカナ2字以上）を抜いて突き合わせる。
- 接尾の 的/化/性/さ/み は落として比較する（「深刻化」と「深刻」を同一視するため）。
- 部分文字列では照合しない。「暫定的」と「決定的」が “定的” で衝突する誤検出が出た。
- 意味が正反対で良い誤答になるもの（phase out ⇔ 段階的に導入する＝phase in）は
  `ALLOW_CORE_SHARE` に**理由つきで**例外登録する。理由を書けないものは例外にしない。

### 5. 熟語パートは易化しやすい
準1級 対策問題集で実際に指摘された事故（put off / carry out / keep up with が2級級）。
`TOO_EASY_IDIOM` で中学〜2級の句動詞を禁止し、各回ちょうど4つ入っているかも数える。

### 6. 用例に見出し語が実在するか（G8）
`usage_en` に見出し語の語幹が含まれることを機械照合する。
不規則変化（wear off → wore off、fall through → fell through）は `USAGE_IRREGULAR` に
理由つきで登録。ここを緩めると「用例が別の語の例文」という事故が通る。

### 7. 解答解説編は各回の実施後に配る前提 → メモの「先出し」が漏洩になる（G13）
第1回 deter のメモに「名 deterrent」と書くと、deterrent は第8回の見出し語なので
その回は必ず正解される。同型で deficit の「⇔ surplus」（surplus は第5回）、
sanction の用例 `impose economic sanctions`（impose は第9回）も検出。
**盲ソルバーは1問しか見ないので構造的に検出できない**。Python で全メモ・用例を
「後の回の見出し語」に対して走査する。

### 8. 表紙の数字はデータから数える（`build.stats()`）
過去の問題集で「表紙に112問と刷って実際は103問」という事故がある
（**3人の盲ソルバー全員が素通り＝解く人は表紙を見ない**）。
回数・問数・単語/熟語の内訳・満点・目標点はすべて `stats()` が実データから生成する。

### 9. 印刷物に「実測していない事実」を書かない
初版は各回に「最頻出①」「頻出②」「差がつく③」という頻度ラベルを付けていたが、
語彙リストと突き合わせたところ**「最頻出」の回のほうが実際には難しい**（第1回の平均頻度順位
1722 に対し第5回1153）と分かった。裏の取れない主張は配布物から外し、テーマ表示のみにした。

## 検証の層（どれか1つでも省くと必ず漏れる）
1. `check.py` の機械ゲート **G1〜G20（G16は欠番＝19本）**（何度でも回せる。AIレビュー1本より安い）
2. `scripts/_pdf_qa.py` — グリフ監査＋ページ別文字数（空白ページ・はみ出し検出）
3. 独立レビュー3系統（報告の**前**に回す。最終確認ではない）
   - 盲ソルバー2名（唯一解の確認 / 第2正解探し）→ `reconcile.py` が Python で照合
   - 語義・用例・note の事実確認とレベル妥当性（WebSearch で一次情報に当たる）
   - 冊子横断の不備（解答漏洩・表紙の数字・解答一覧の一致）

### ★200問→400問に増やしたとき出たこと（第11〜20回の追加・2026-08-05）

**5人に分担して書かせ、親（統合側）が横断を検査する**形にした。ルールは `RULEBOOK_11_20.md` に
外部化してある（このREADMEの事故から作った R1〜R8）。`merge_drafts.py` が
「割り当てと違う語／誤答3つ未満／必須欄が空」を弾いてから content.py に入れる。

分担したことで**担当が自分の担当外の実害を見つけた**のが収穫だった:
- 既存の第1〜10回のメモ **12件**が、新しく足した回の見出し語を先出ししていた
  （`consensus`のメモが`census`、`ascertain`が`assert`、`allegation`が`allege`…）。
  ★**新しい回を足すと、前からあるメモが遡って漏洩に化ける**。追加のたびに全方向で洗い直すこと。
- `carry out` / `get along with` が `TOO_EASY_IDIOM`（2級以下）に該当 →
  `follow through on` / `take after` に差し替えた。
- ★**G5 が「最短と最長」しか見ていなかった**。ある原稿は最短10.2%・最長8.1%で両方合格なのに
  **「中間の長さの肢を選ぶ」が44.4%**取れていた。→ G5 を**4順位すべて**測る実装に直した。

**組版**: 選択肢が長くなると1行に収まらず行が2倍になり、20問のどこか1問で溢れると
次ページがほぼ空白のまま1枚増える（実測 25ページ・空白4枚）。`qw=46mm / qc=8.5pt` で21ページに収めた。
★**build 後に必ず `scripts/_pdf_qa.py` を通す**こと。

**表紙**: 問題編は `stats()` で実データから数えていたが、**解答解説編の表紙だけベタ書き**が残り、
400語に増やしたのに「全10回 × 20語 = 200語」と刷られた。
→ build.py が**書き出した HTML を読み返して**表紙の数字と実データを突き合わせ、違えば止める。
「数えて作る」だけでは足りず「刷る直前に読み返す」層が要る。

### ★しきい値を決め打ちすると、ゲート自身が偽陽性の機械になる

`G5` は当初「回ごとに 40%(=8/20問) を超えたら FAIL」だった。第1回が **8.0000** で、
FAIL 条件は `> 8.0` ——**紙一重で通っていただけ**。正解位置を無作為化した帰無分布では
**70%の確率でどこかの回が鳴る**（2順位×10回 → 4順位×20回 と検定回数が4倍になったため）。
次に1語足した時点で、健全なのに落ちる。

→ `rank_limits()` が**実データの同点構造から**上限を計算する方式に変えた。
正解位置を一様乱数にしたときの1問あたりの分散は `1/(4c) - 1/16`（c＝同値の肢の本数）。
同点が多いほど厳しくなり、問数が少ないほど緩む。

★**4順位の分散を平均してはいけない**（最初これをやって指摘された）。同点の多い順位は分散が
小さく、無い順位は大きい。平均すると**同点の多い順位が緩くなって見逃す**。実効 z が 2.2〜3.2 に
ばらついており、**いちばん緩かったのが「漢字が最少」——40.2%の事故が起きたまさにその順位**だった。

★**z も順列検定で較正する**。`rank_gate` は長さと漢字の2キーで呼ばれるので検定は
4順位×3範囲×2キー＝**24回**。z=2.6 ではゲート全体の偽陽性が **11.7%**（宣言していた5%の2.4倍）
あった。順位ごとの分散に直したうえで z=2.9 にして約5%。

★**ゲートを直したら、必ず「わざと壊して落ちるか」を確かめる**。
過去6世代の欠陥（最長78%・最短34.5%・2番目33.6%・中間44.4%・熟語の漢字40.2%）を
再現するデータを作って **6/6 検出**、素のデータは通ることを確認してある。
★このとき**自己テストの方が壊れていた**: 最初は「選択肢の位置を入れ替える」実装で、
正解の長さ自体が変わらないため何も歪んでおらず 0/6 と出た。
**「検出できなかった」を見たら、まずテストを疑う。**

### ★同語源の対が回をまたぐと、先の回の解説だけで後の回が決まる（G20）

G19（メモ・用例訳）を足してもまだ足りなかった。**解答解説編は意味欄も刷る**ので、
第8回 `testimony` の意味「証言」を配った時点で第12回 `testify` の正解「証言する」は決まる。
★このとき用例訳だけ「法廷で証言する」→「法廷で証言を行う」と**言い換えてもゲートは緑になる**
（意味欄が残っているため）。**言い換えですり抜ける**の実例。

対策は G20。判定は「**日本語を文字列照合するだけで当たるか**」に一本化する:
1. **熟語が丸ごと再利用される**（`account for` ⊂ `account for the bulk of`）＝英語を1語も
   知らなくても同じ熟語だと分かる → **無条件で不可**。`by and large` に差し替えた。
2. 単語の派生（見出し語の包含 or 語幹4字共通）は、**後の回の答えが先の回の解説ページ
   （意味欄・用例訳・メモ）に日本語として載っているとき**だけ落とす。
   語形から導ける分（`deter`→`deterrent` を「思いとどまらせるもの＝抑止力」と推す）は
   このテストが測りたい語彙力そのものなので落とさない。

設計で効いたこと（どれも一度は間違えた）:
- **「語幹が同じ」だけでは広すぎる**。`comply`/`compile`/`compensate` まで拾って30件の誤検出。
  →「語幹が共通 **かつ** 日本語の意味も重なる」に絞った。
  `considerable`(かなり多い)/`considerate`(思いやりのある) のような**意味の違う紛らわしい対は落とさない**。
- ★**「語幹に正規化した」つもりで、実際にはしていなかった**。`_TAIL` は語尾しか落とさないので、
  `allegation` の意味欄を「申し立て」→「**申立て**」と書くだけ（意味は同じ）で検出が消えた。
  → **かなを全部落とした骨格**（`_bone`）で照合する。語中の送り仮名も表記ゆれも吸収される。
- ★**骨格が1文字以下になる語義で空振りしていた**。「思いやりのある」→ 思、「〜から成る」→ 成、
  「おさまる」→ 空。部分文字列を2文字以上しか作らないので `keys` が空になり、
  **意味欄に答えを丸ごと書いても鳴らなかった**（157対中32対が該当）。
  → 骨格が短いときは**かな込みの語義そのもの**で照合する。
- **部分文字列の総当たりも広すぎる**。「自己主張」から「主張」まで拾って誤検出。
  → **先頭からの切り出し**にした（「抑止力」→「抑止」は拾い、「自己主張」→「主張」は拾わない）。

これで直したのは `assert` の意味欄「主張する」、`consist of` の「構成」、`advocate` のメモ
「支持者・提唱者」、`deter` の意味欄「抑止する」。`inference` は `infer` に丸ごと含まれ、
答えの「推論」も第12回の解説に出るので **`connotation` に差し替えた**。

**残した例外は `testimony/testify` と `allegation/allege` の2組だけ**（`ALLOW_SAME_ROOT`）。
★ただし**反対意見がある**: 「testi- / alleg- という綴りの近さに気づけば足り、語形の対応を
見抜く語彙力は要らない」。もっともな指摘で、本筋の対処は**同じ回に置く**こと。
いまは回のテーマが崩れるのを避けて据え置いており、**次に回を組み替えるときに同居させる**。

### ★メモは「英単語を出さなくても」漏れる（G19）

G13 は**英語の見出し語**の先出しを見張るが、それだけでは足りなかった。
**日本語の語義だけ書いても、後の回の答えは渡ってしまう**。
- 第16回 `considerable` のメモ「**「思いやりのある」**意味の似た形の語と混同注意」が、
  第18回 `considerate` の正解「思いやりのある」をそのまま書いていた。
- G19（メモ・用例訳に後の回の正解語義が出ていないか）を足したら、**さらに4件**出た
  （`surge`→proliferate「急激に増える」、`undertake`→set out「着手する」、
  `testimony`→testify「証言する」、`negligible`→marginal「ごくわずかな」）。
  ★**人のレビューは1件しか見つけられなかった**。この型は機械で全数照合するしかない。

**綴りの近い語を注意するときは、相手の語義を書かない**（「綴りの近い別語と取り違えやすい」
とだけ書く）。同語源の対（testimony/testify、considerable/considerate）は**同じ回に置くのが本筋**。
別の回にまたがると用例訳にも漏れ、避けるたびに日本語が不自然になる。

### ★解答解説編は「1冊まるごと渡す」と全回の答えが渡る
20回分が1冊に綴じてあるので、第1回の返却で丸ごと渡すと残り19回の答えが伝わる。
**1回＝1ページ**の作りにしてあるので、実施した回だけ切り離して渡す。
全回の正解が1枚に載る「解答一覧」は**指導者控え**（表紙と当該ページに明記済み）。

### ★長さの次は「字面」だった — 熟語だけ漢字の量で解けた（G18）

長さ4順位を平らにしたら、今度は**文字種**が目印になった。
**熟語問題だけ「漢字が最少の肢を選ぶ」で 40.2%**（単語は27%で無害）。
原因は、熟語の語義は自然と和語（ひらがな主体）になる（「うまくいく」「〜のおかげで」
「〜のなすがままで」）のに、**誤答だけ漢語で書いていた**こと。誤答23問を和語調にそろえた。

★またしても**片側だけ潰して反対側が立った**（長さで2回、字面で1回＝計3回目）。
最少を16.8%まで下げたら「2番目に少ない」が33.2%になり、7問戻して平らにした。
**G18 は G5 と同じく4順位すべてを測る**実装にしてある。
- 熟語80問の最終値: **22.1 / 29.4 / 25.0 / 23.5 %**（上限は `rank_limits()` が実データから算出）
- ★**n が小さい部分集合はしきい値を上げる**。熟語80問では1問=1.25pt 動くので、
  30%固定だとゆらぎを欠陥と誤認して延々に直し続けることになる。

★**漢字を減らす調整で、通常の表記に無い混ぜ書きを作らないこと**。
「空回りする」を「から回りする」にして日本語として壊した（機械では捕まらない。盲レビュー層が拾った）。
開くなら全部開く（「からまわりする」）。

### ★「紛らわしい語」の回は、辞書が割れる向きに作ると2正解になる（第18回）

第18回は「綴りの似た相手の語義を誤答に置く」設計（`economical`「むだのない」の誤答に「経済の」）。
ところが**記述的な辞書は見出し語自身にも相手の語義を立てている**ことがある。
- LDOCE は `continual` の**語義1**を「止まらずに続く」とする → 誤答「途切れのない」が第1義そのもの＝2正解。
  （Wiktionary はこの用法を proscribed と明記し、研究社は「断続的な」とする。**辞書が割れる**。）
- MW は `historic` の語義1に HISTORICAL、`economical` の語義3に ECONOMIC を立てる。

**典拠は学習者向け辞書（LDOCE / Cambridge Learner's / Oxford Learner's）に寄せる**。
母語話者向け・記述的な辞書（MW / Wiktionary）は参考にとどめる。読者が日本の高校生だから。
★この基準で3辞書を実際に引かせたら、**指摘5件のうち当たったのは1件だけ**だった
（`economical`「経済の」＝Cambridge が economical に "relating to the economy" を載せている）。
`historic`「史実に基づく」・`sensible`「敏感な」・`alternate`・`virtual` は3辞書とも
見出し語の語義に立てておらず**誤指摘**。★MW を根拠にすると直さなくていいものまで直すことになる。

実際に直したのは3件:
| 語 | 誤答 | 典拠 |
|---|---|---|
| `continual` | 途切れのない → 一斉に起こる | LDOCE 語義**1**「止まらずに続く」／OALD も同旨 |
| `economical` | 経済の → 豪華な | Cambridge「relating to the economy（Syn: economic）」 |
| `historic` | 古めかしい → 目立たない | LDOCE 語義1「a historic building is **very old**」と接近 |

★**地雷メモ**: `alternate` の誤答に「代わりの」を置いてはいけない
（OALD/Cambridge が米用法として alternate 自身に立てている）。`continual` のメモも
「間が空かず続く意味の語と区別する」と断定していたが、OALD の Which Word? が
「両者の差は消えつつある」と明記しているので緩めた。
★**この型は「対を作る向き」で決まる**。「格上の語」が「格下の語」の意味を吸収している向きが多いので、
2正解が立つときは**逆向き（格下の語を見出しにする）**にすれば消える。ただし格下の語は易しいので級が下がる。
今回は級を優先し、誤答の側を差し替えた。

### ★具体物ダミーは1問1本まで（G17）
正解の語義は抽象・改まった語なので、**物理的な具体物を指す肢は構造的に必ず誤答になる**。
実測で35本すべて誤答。1問に2〜3本入ると「具体物を消す」だけで実質2択・0択になり、
`water down`（水をやる／洗い流す／水中に沈める）と `testimony`（遺言／身分証明書／遺言の執行人）は
**誤答3本とも具体物＝答えが確定**していた。綴り混同を狙うダミー
（deterrent/detergent、peril/pearl、mundane/Monday…）は教材として価値があるので全廃せず、
**1問1本に制限**して差し替えた（35本→26本・26問）。

### ★どこで止めたか（残っている tell を隠さない）
★**この節の測定は第1〜10回の200問だけ**（`tells_final.json` が旧 `blind.json`（200問）の
sha1 に紐づいていた。そのファイルは 400問化のときに削除した）。**第11〜20回の200問は
58本の手作りルール走査を通していない**。下の「抜け道は残っていない」は 200問の範囲の結論で
あって、400問全体の保証ではない。走査を再現するスクリプトはリポジトリに無いので、
やるなら作るところからになる。★ここを「全部見た」と読ませないために、この但し書きは消さないこと。

最後の抜け道スキャンで、**日本語の選択肢だけを使った文字n-gramベイズ分類器が
交差検証で 39.9%**（ランダム25%）を出した。原因は「正解＝この単語帳のテーマ語彙
（損な・抑制・格差・影響・低迷）／誤答＝日常語（修復・試験・治療・居住・吸収）」という
**レジスタの差**。これは**直さないと決めた**。理由:
- 学生が紙の上で使える手ではない（160問で学習して40問を当てる分類器が必要）。
- 手作りルールは58本すべて28%以下（帰無最大34.9%の範囲内）＝**第1〜10回の範囲では**
  人間が使える抜け道は残っていない（第11〜20回は未走査）。
- C1語の正しい訳語は本質的に抽象語なので、これを消すには誤答も全部抽象語にする必要があり、
  誤答の妥当性（＝紛らわしさ）を犠牲にする。教材としては逆効果。

同様に残す判断をしたもの: 具体物ダミー26問（1本まで＝消せても3択どまり・+1.1%）、
反意ペアが見える23問（+2.9%）。いずれも「知っていれば消せる」＝語彙力の一部でもある。
**合格条件は「人間が使える戦略が30%を超えないこと」**であって、機械学習器を
偶然水準まで落とすことではない、と定義して打ち切った（第1〜10回について）。
なお 400問全体で毎回走る機械ゲートは `check.py`（正解位置・長さ順位・語義の共有など G1〜G20）と
`check_cefr.py`（収録語のレベル）で、こちらは全400問が対象。

### ★見出し語を1文字でも変えると正解位置が動く
`assign()` は `md5(salt + word)` 順に位置を振るので、`on par with` → `on a par with` の
ような**綴りの修正だけでその回の正解位置が入れ替わる**。実際に第10回で4問ずれ、
盲ソルバー4名が全員そろって鍵と違う答えを返した（＝一見「鍵誤り」に見える）。

**この見分け方が要点**: 全員が一致して外すのは、鍵誤りか**位置の移動**のどちらか。
`旧配列でソルバーが選んだ文字列` と `新配列の正解文字列` を突き合わせれば
Python で確定できる。同一なら位置が動いただけで解答内容は正しく、盲検証をやり直す必要はない。
（今回は4問とも同一で、200問すべて内容一致を維持した。）

### ★機械ゲートにできなかったもの
「印字語義と用例訳が別の語義になっている」型（induce の語義順を入れ替えたら用例
`induce sleep（眠気を誘う）` が取り残された）は**ゲートにできなかった**。
`cores()` は漢字2字以上しか核にしないので「〜を罰する／違反者を罰する」のような
完全に対応した組まで「核が無い」と誤検出し、実装すると73件中ほぼ全部が誤報になる。
**本物の警告が埋もれてゲート全体が信用されなくなるので、入れずに外した。**
この型は辞書照合レビュー層で拾う。★語義の順序を入れ替えたら用例を必ず読み直すこと。

★盲ソルバーには**番号の起点を必ず明示する**（1始まり）。このリポジトリで 0/1 始まりの
取り違えにより「四択が全問ずれて鍵誤りに見える」事故が再発している。`blind.json` の
`answer_format` にその旨を書いてある。

## レベルの実測（2026-08-19・全320語を一次情報で照合済み）
`check_cefr.py` が `_cefr_levels.tsv` と `content.py` を毎回突き合わせる。**手作業ではない**。

Oxford 公式 *The Oxford 3000/5000 by CEFR level* と**全320単語**を照合した結果:

| | 件数 |
|---|---|
| B1 | **2**（第18回 `sensible` / `historic`） |
| B2 | 47 |
| C1 | 123 |
| Oxford 3000/5000 圏外 | 148 |

- **リストで裏が取れた172語のうち170語が B2 以上**。A1〜A2 は0件。
- ★**圏外148語は「B2 以上」ではない**。Oxford 3000/5000 は**頻度上位5000語の抜粋**であって
  A1〜B1 の網羅リストではない（`pillow` `kettle` `strawberry` のような日常語も載っていない。
  2026-08-19 のレビューで実証）。圏外は「**頻出上位5000語より外**」という事実だけで、
  レベルの根拠にはならない。表紙もこの2つを分けて書いている。
  ★148語（46%）のレベルは今も裏が取れていない。断言したいなら EVP など別の一次情報が要る。

  `historic`（歴史に残る／historical と対比）は語そのものは B1 でも、**その語義の識別**が準1級の頻出事項。
  `check_cefr.py` の `ALLOW` に理由つきで登録してある。

### ★2026-08-19 まで、表紙が未検証の範囲まで断言していた
問題編の表紙は「**収録語はすべて CEFR B2〜C1（準1級相当）以上です**」と刷っていたが、

→ 表紙は「収録語320語のうち、Oxford 3000/5000 に載る172語は170語が CEFR B2 以上。

   ★**圏外を B2 以上に数え込まない**。数字は `build.py::cefr_stats()` が tsv から数えて刷る。
→ `check_cefr.py` が (a) 表紙に「すべて」の言い切りが無いか (b) 数字がハードコードされていないか

★紙は刷ったら直せない。レベルの主張は毎回機械で照合すること。

### 語を足すときの手順
1. Oxford の一覧（https://www.oxfordlearnersdictionaries.com/wordlists/oxford3000-5000 で
   `Oxford 5000` を選ぶ）でその語を引く
2. `_cefr_levels.tsv` に `見出し語 <TAB> 品詞 <TAB> レベル` を1行足す（無ければ `-` と `NOT_LISTED`）
3. `python3 check_cefr.py` を通す。**tsv に無い語があれば FAIL する**ので、調べ忘れは止まる
4. 表紙の数字は直さなくてよい。`build.py::cefr_stats()` が tsv から数えて `%d` で刷る。
   ★**手で数字を書き込むとゲートが FAIL する**（ハードコード検出）。文言を変えるときは
   `check_cefr.py` の探し方（`'収録語...'` の正規表現と `pats`）も一緒に直すこと

★`check.py` の `TOO_EASY_IDIOM` は**熟語の易化しか見ていない**。熟語（80）のレベルは
Oxford 3000/5000 に載らないので `check_cefr.py` の対象外。熟語側は従来どおり `check.py` が見る。
