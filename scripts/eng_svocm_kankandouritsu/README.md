# 英文解釈 × SVOCM 判別（関関同立）

関関同立志望の高校生向け。**単文レベルで「骨組みを記号で指せる」ところまで上げる**プリント。
長文の中で分解する `../eng_hinshi_bunkai/`（高校標準〜MARCH）へ上がる前段。

    問題編 / 解答・解説編 の 2 冊
    第1部 SVOCM 判別 30 問（Ａ 骨格 12 / Ｂ 修飾語を切り離す 9 / Ｃ 誤読しやすい形 9）
    第2部 構造判断の 4 択 12 問
    第3部 英文解釈（分解＋和訳）21 文
    合計 63 問 / 62 構文

## 使い方

    python3 check.py           # 内容ゲート（引数なしで刷るもの全部を検査）
    python3 selftest_gate.py   # ゲート自体が落とせるかの変異試験（27 ケース）
    python3 lint.py items.json # 原稿を書きながら回す DSL チェッカ
    python3 build.py           # ~/Desktop に 2 冊を PDF 出力（塾長の Mac でのみ動く）
    python3 make_preview.py out.html  # 画面で読める1枚（PDF を刷らずに中身を確かめる）
    python3 qa_pdf.py          # ★build 後に必ず: 刷った PDF を開いて原稿と逆照合する
    python3 check_level.py            # 語彙レベルを CEFR で測る
    python3 check_level.py --compare  # 実際の入試英文・既存教材と同じ物差しで並べる

`make_preview.py` は同じ `content.py` から画面用の 1 枚を機械生成する（紙と画面で中身はずれない）。
解答の表示・非表示を切り替えられるので、問題編と解答編の両方の見え方をその場で確かめられる。

`build.py` は先に `check.py` を通し、落ちたら刷らない。
PDF 化は Chrome + Arial Unicode を使うので **CI とクラウドの Claude Code では動かない**
（それらの環境では `check.py` / `selftest_gate.py` までを回す）。

## 設計（ここを崩すと教材として成立しない）

### 1. 単一ソース原則を第1部にも広げた
問題編に刷られる `①The news ②made ③everyone …` の区切りは、分解 DSL の**トップレベル要素から
機械的に切り出す**（`layout.top_segments`）。だから「問題用紙の区切り」と「解答の記号」が
ずれることは構造上あり得ない。文型も主節ラベルから再計算して `pat` と照合する
（手入力の「第5文型」を信じない）。

### 2. 表記規約は散文でなく機械で守らせる
この教材は「訳せたか」ではなく **「記号を指させるか」** で採点する。だから
**同じ構文が2通りに書けてはいけない**（正解が一意でなくなる）。規約1〜18 は `lint.py` の
冒頭にあり、`check.py` がそれを import する（契約は 1 か所にしか書かない）。
同じ内容を巻頭の「記号の書き方（この教材の約束）」として**紙にも刷る**。
`check.py` は表が 8 行未満になったら落とす。

★実際に、4 巡の講評で見つかった揺れはすべてこの層だった:
助動詞の併合／ダッシュの深さ／括弧とラベルの対応／分詞と to 不定詞の分解／
同格と挿入と非制限用法の区別／of 句の粒度／群動詞／英米綴り。

### 3. 構文の割り当て表（`content.py` の `SYN_POOL`）
「何を教えるか」の設計図。グループごとに**重ならないプール**を宣言し、`check.py` が
**プール外の構文**と **宣言したのに出題されていない構文** の両方を落とす。

★重複を `tag`（自由文）で数えると、書き換えるだけですり抜けられる。実測で
「同格の that 節が3問・分詞の後置修飾が4問」ある一方、
「仮定法・付帯状況の with・相関接続詞・複合関係詞・so ... that・too ... to・that of」が
**1問も無い**状態を、tag では見つけられなかった。

★割り当て表は `content.py`（原稿）に置く。`layout.py`（共通コード）に置くと、原稿がまだ
骨格しか無い段階でも 60 問ぶんの設計を宣言したことになり、**宣言と中身が食い違ったまま
コミットされる状態**ができる。

## レベルの主張は測ってから言う（2026-09-01 の実測）

「関関同立レベル」と紙に書くのは**測定を伴う主張**なので、`check_level.py` で機械照合する。
物差しは Oxford 3000/5000 の CEFR レベル（`_cefr_oxford5000.tsv`・出典と取得日を先頭に記載）。

    関西学院 英語（実物）            A1+A2 61.6%  B1+B2 24.4%  C1+一覧外 13.9%
    品詞分解（高校標準〜MARCH・既存） A1+A2 76.5%  B1+B2 17.2%  C1+一覧外  6.3%

    この教材 第2部（構造4択）        A1+A2 87.7%  B1+B2 10.4%  C1+一覧外  1.8%

★**第3部は実物の帯に合わせてある**（同志社と関学のちょうど間）。
  第1部・第2部は**判別ドリルなので語彙をやさしく保つのが正しい**（語彙で落とすと
  構文を見る訓練にならない）。ここを上げないのは設計上の判断であって、測り忘れではない。
  実物との差は表で判断する設計にしてあり、ゲートは明らかな帯外れ（A1+A2 > 85% 等）だけを落とす。
  原稿を書きながら測るときは `python3 check_level.py --file draft.json`。

★大学別分析（`../doshisha_eigo_mirror/overview_seki.txt` 等）が名指しする
  **No sooner … than / neither … nor / as if** は第3部に収録済み。

★物差しそのものが狂うことがある。最初の版は多品詞の語で**高いほうの**レベルを採っており、
  say（名詞の a say が C1）や sound が C1 に化けて、ごく普通の語を「重い語」と数えていた。
  語の CEFR レベルは「最初に習うレベル」＝**低いほう**を採る。

## ★紙は必ず自分の目で見る（機械だけでは緑のまま壊れる）

`check.py` は原稿と組版**結果の文字列**を見るが、それだけでは紙の崩れは見えない。
実際に、全ゲートが緑のまま次の 3 つが刷られていた（PNG に起こして目視して初めて分かった）:

1. **追加 CSS が 1 文字も紙に届いていなかった**。`build.py` が `layout.BASE_CSS` に**代入**して
   いたが、組版する `doc()` が読むのは共有コア側の変数。第1部の解答欄が罫線も枠も無い
   素のテキストで刷られていた。→ `layout.install_css()` を使うこと。
2. **二重エスケープ**。`&lt;` を含む文字列を `esc()` に通して `&amp;lt;` になり、
   紙に `&lt;` という文字がそのまま出ていた（巻頭の記号ルール）。
3. **見出しだけのページ**。57 行の索引に `page-break-inside:avoid` が効いて表が丸ごと
   次ページへ送られ、見出しだけのページができていた。

3 つとも `check.py` のゲートにした（本文で使う class が全部スタイルシートに定義されているか /
二重エスケープが無いか / 中身の薄いページが無いか）。変異試験でも固定してある。

★**この環境（クラウド）で刷った PDF は Noto で組んでいる**。塾長の Mac はヒラギノ + Georgia
  なので、**行分けとページ数は変わる**。中身の照合は有効だが、ページ数は最終ではない。

## 踏んだ穴（同じ所を掘り直さないために）

- **`layout.py` を `core.py` という名前にしてはいけない**。隣の `eng_hinshi_bunkai/` にも
  `core.py` と `content.py` があり、`sys.path` 経由だと `import content` が**隣の教材の原稿**に
  当たる。共有コアはファイルパスを名指しして読み込んでいる。
- **巻頭の例文が本編の答えを先に見せる**。表記規約の例に書いた
  `a growing number <M: of manufacturers>` が第1部Ｂの問題の答えそのものだった。
  巻頭の例文と本編の英文を全数照合するゲートを入れたら、**入れた直後に自分が書いた例文を
  3 回落とした**。照合は**語形変化まで見る**こと（`take advantage of` と `taken advantage of`）。
- **丸数字が刷られるのは第1部だけ**。第2部・第3部の解説が「②did と④notice が」と書いていたが、
  それらの解答カードは分解図を出すだけで番号を振らない。生徒には何のことか分からない。
- **変異試験は「危ない入力が検査の見える位置に無い」形でも試す**。
  ・4択の正解位置の偏りは、問題数が 3 問以下だと原理的に発火しない（第2部が 1 問のとき空振りした）。
  ・割り当て表の充足を「全体での使用」で見ると、別グループで使われている構文を自分のプールに
    書き足しても素通りする（プールごとに見るよう直した）。
- **自分のゲートが正しい原稿を落とす**ことがある。実測した誤検出と、その除外規則:
  ・`{C:extremely difficult}` を「原形不定詞の分解漏れ」と誤検出
    → `make` は C に形容詞も原形も取るので V だけでは決められない。形容詞に見える語で始まる C は対象外。
  ・`{V:has become}` の `has` を使役動詞と数えた → have/has/had は**1語だけのとき**に限って使役と見る。
  ・`{V':to rethink}` を「準助動詞の to」と誤検出 → 先頭の to は不定詞そのもの。2語目以降の to だけを見る。
  ・`( M': to the police )` を「素の to 不定詞」と誤検出 → to の次が冠詞・限定詞・大文字なら前置詞。
  ・`「workers に unable … を与える」` を「本文に無い英語の引用」と誤検出
    → 鉤括弧の中に日本語が1文字でも混ざっていれば引用ではない。

   `check.py` が組版結果（`build.build_mondai()`）を読み返して、答えの先出しと刷り漏れを見る。
2. **機械検査** — `check.py`（DSL 契約・表記規約・割り当て表・正解位置・重複・グリフ）と
   `selftest_gate.py`（27 種の故意の欠陥を注入して、ゲートが落とせることを確認）。
3. **人手の再点検** — 正解の一意性は機械では見えない。全問を敵対的に読み直す工程を
   4 巡回し、指摘は 30 → 26 → 17 → 11 件と減った。
   ★**残った指摘のほとんどは「図と訳と採点観点が別のかかり先を指している」型**だった。
     機械は図の一貫性しか見られないので、ここは必ず人が読むこと。
