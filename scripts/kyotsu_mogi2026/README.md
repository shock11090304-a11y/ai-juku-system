# 共通テスト模試 2026 (英語・数学)

大学受験生向けの共通テスト形式 模試問題。`mock-exam.html` の「画面で受験する模試 (AI採点)」から
そのまま出題される `exam_questions` プールに投入する。

## 何がどこに入るか

| 模試テンプレ (`MOCK_EXAM_TEMPLATES`) | セクション | プール枠 `(exam_id, part_key, eiken_grade)` | 今回の追加 |
|---|---|---|---|
| `kyotsu` 共通テスト英語 (リーディング相当) | 短文読解 | `(daigaku, r_short, kyotsu)` | 4 大問 / 17 小問 |
| | 長文読解 | `(daigaku, r_long, kyotsu)` | 5 大問 / 25 小問 |
| `kyotsu_math` 共通テスト 数学 (IA・IIB) | 数学I・A | `(rikei, math_1a, kyotsu_rikei)` | 6 大問 / 30 小問 |
| | 数学II・B | `(rikei, math_2b, kyotsu_rikei)` | 6 大問 / 30 小問 |

合計 **21 大問 / 102 小問**。テンプレが 1 回に引くのは英語 2+3 大問・数学 3+3 大問なので、
この追加分だけでも毎回違う組み合わせの模試が成立する (既存プールとも合算される)。

全小問が `multiple_choice` なので `mock_exam_submit` の自動採点に載り、
小問ごとの `unit` タグが `question_attempts` に落ちて弱点分析・単元ドリル推薦につながる。

## 印刷用 PDF (紙の模試)

同じ seed JSON から、印刷して配れる冊子も生成する。アプリの出題内容と完全に同じなので、
問題文を二重に管理しなくてよい。

| ファイル | 内容 |
|---|---|
| `kyotsu-mogi2026-eng-mondai.pdf` | 英語 問題編 (80分・100点満点・解答用紙つき) 20ページ |
| `kyotsu-mogi2026-eng-kaisetsu.pdf` | 英語 解答・解説編 (正解一覧 + 設問別解説) 12ページ |
| `kyotsu-mogi2026-math-mondai.pdf` | 数学 問題編 (I・A 120点 / II・B・C 120点・解答用紙つき) 17ページ |
| `kyotsu-mogi2026-math-kaisetsu.pdf` | 数学 解答・解説編 17ページ |

数式は `vendor/katex` を **node 側で静的レンダリング**してから流し込む。印刷時に JS の実行完了を
待たなくてよいので、「数式が欠けた PDF が出る」事故が構造的に起きない。
KaTeX が解釈できない式が 1 つでもあればビルドが落ちる。

解説は 2 つの正規フォーマットをそれぞれの見え方に組む。数学の「方針/立式/計算/答え/補足」は
ラベル付きの段組み、英語の 4 セクションは小見出し + 箇条書きになる。
★ **整形は必ず LaTeX 描画の前**に行うこと。KaTeX の出力は `\sqrt` 等の SVG path に改行を含むため、
描画後に行分割すると path データが本文として露出する (2026-08-02 に実際に発生させた)。

配点は英語が大問ごとに 2〜3 点で合計ちょうど 100 点、数学は 1 小問 4 点 (1 大問 20 点)。
数学は本番が 70 分 4 大問なので、表紙に「第1問〜第4問 (80点) を選べば本番と同じ分量」と明記してある。

## 手順

```bash
# 1. 生成 (検証込み・失敗したら非ゼロ終了して JSON を書かない)
python3 scripts/kyotsu_mogi2026/build_eng.py
python3 scripts/kyotsu_mogi2026/build_math.py   # 要 sympy

# 2. 取込前チェック (server/main.py の実定義と突き合わせ)
python3 scripts/kyotsu_mogi2026/preflight.py

# 3. 印刷用 PDF (要 node + playwright。Chromium は /opt/pw-browsers に既設)
python3 scripts/kyotsu_mogi2026/build_pdf.py

# 4. 本番投入 (CRON_SECRET は環境変数から)
railway run -s ai-juku-api python3 scripts/kyotsu_mogi2026/import_prod.py
```

`import_prod.py` は `--dry-run` で件数だけ確認できる。`eng` / `math` を引数に取ると片方だけ投入する。

PDF を出したあとは、`pdftotext -layout` で抜いた正解一覧が JSON の `answer` と一致するか
突き合わせておくとよい (102/102 一致を確認済み)。組版の過程で解答がずれていないことの最終確認になる。

## 準拠しているルール

問題そのものより先に、**このリポジトリで既に決まっている出題ルール**に合わせてある。
ルールの所在は `server/main.py` の生成プロンプトと、同一プールの既存 seed。

### 解説フォーマット (必須)

| 科目 | 規定 | 出典 |
|---|---|---|
| 数学 | 「考え方→立式→計算→答え→補足」を必ず段階分け (3行以上) | `server/main.py` 理系生成プロンプト |
| 英語 | `## 🎯 コアイメージ` → `## 🔬 文構造分析` → `## 📍 本文の根拠` → `## ❌ 誤答 NG 理由` の**4セクション必須**「1セクションでも欠けたら不合格」 | `server/main.py` 英語系生成プロンプト |

数学は同一プール `(rikei, math_1a/math_2b, kyotsu_rikei)` の既存 seed
`rikei_kyotsu_math_manual.json` (148問) と**同じ 5 行構成**にした。

英語は 4 セクションに加えて、同一プール `(daigaku, r_short/r_long, kyotsu)` の既存 seed
`dojo_eng_kyotsu2026_manual.json` (140問) の慣行どおり冒頭に
`正解は「<正答の選択肢テキスト>」。` を置く。これで
`scripts/eng_kyotsu_2026/validate_and_build.py` の検査にも通り、
解説と選択肢の食い違いを機械検出できる。

**どちらも build 時に強制する。** 数学は 5 セクションの存在と「答え:」に正答テキストが含まれること、
英語は 4 セクションの存在・順序・誤答理由が誤答 3 件と 1 対 1 対応することを検査し、
違反があれば JSON を書かずに落ちる。フォーマット違反は本番に流れない。

### その他の遵守事項

- **choices 配列**: `multiple_choice` は必ず非空・4 要素 (`server/main.py`「choices 配列の絶対遵守ルール」)。
- **整合性 self-check 1〜5**: stem と answer と choices が三者整合し、
  「正解が選択肢にないので別のものを選ぶ」式の言い訳が解説に無いこと。
  数学は sympy による独立再計算で構造的に担保している (下記)。
- **unit タグ**: `dojo-drill.html` の `deriveUnit()` が `q.unit` を最優先で読むため、全小問に付与。
  弱点分析・単元別ドリルの分類と揃えてある。
- **自己完結ゲート Layer A**: ベクトルの小問は成分を必ず stem に書く。
  成分が解説にしか無いと `_self_containment_gate` が「解けない問題」として取込時に弾く。

## 品質ゲート

**数学** — 正解を手で書かない。各小問は `correct` / `distractors` を「LaTeX と sympy 値」の組で持ち、
`verify()` が別の道筋で独立に再計算する。両者が一致しなければ `build_math.py` は JSON を書かずに落ちる。
60 小問すべてがこの照合を通っている。誤答も sympy で正解と同値でないことを確認済み
(別表記の同一値がまぎれ込むと「正解が 2 つある問題」になるため)。

**英語** — `scripts/eng_kyotsu_2026/validate_and_build.py` と同じゲートを `build_eng.py` に実装。
選択肢の重複がないこと、HTML エンティティが残っていないこと、
図依存表現 (`the figure above` 等) を含まないことを検査する。
本文中の表はすべて文字だけで組んであり、画像なしで解答できる。

**共通** — 正解位置は md5 順の round-robin で 0〜3 に完全均等配分 (英語 11/11/10/10、数学 15/15/15/15)。
ハッシュの剰余だけだと実測で 11/19/15/15 まで偏り、当てずっぽうが有利になるため順位で割り当てている。

**preflight.py** — `server/main.py` を実際にパースして次を確認する。

1. `(exam_id, part_key, eiken_grade)` が `EXAM_QUESTION_ROTATION` にあるか (無いと全行 `invalid rotation`)
2. `MOCK_EXAM_TEMPLATES` の該当模試が必要な大問数を引けるか
3. 自己完結ゲート Layer A (`_self_containment_gate`) に掛からないか (掛かると黙って捨てられる)
4. `mock_exam_generate` / `mock_exam_submit` の採点式を再現し、全問正解が 100% になるか

## 注意

- `import_prod.py` は同一プールかつ `question_data` 完全一致を `skipped_dup` で弾くので、二重実行しても重複しない。
- **選択肢の記号**: PDF は共通テストに合わせて ①②③④ を使う。
  アプリ側は `mypage.js` / `class.html` が ①②③④、
  `mock-exam.js` / `dojo-drill.html` が `A. B. C. D.` と割れているので、
  紙で解いてからアプリで答え合わせをすると番号の呼び方が変わる。
  揃えるなら `mock-exam.js` の `String.fromCharCode(65 + idx)` を丸数字に変えるのが最小の修正。
- 問題文・設問はすべて新規に書き起こしたもので、実在の試験問題の転載ではない。
  英語の伝記大問に登場する人物は模試用に作った架空の人物。
