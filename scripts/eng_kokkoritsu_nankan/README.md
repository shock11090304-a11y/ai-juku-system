# 難関国公立大 英文法 実戦問題集

国公立難関大学コース向けの配布用問題集。**私大型の四択を使わず、二次試験が実際に採る形式**
（誤り指摘／語句整序／空所補充記述／英文和訳／和文英訳）で構成する。

## 使い方

```bash
python3 scripts/eng_kokkoritsu_nankan/check.py    # 機械ゲートだけ回す
python3 scripts/eng_kokkoritsu_nankan/build.py    # ゲート→PDF 2冊を ~/Desktop へ
```

`build.py` は冒頭で `check.py` を呼び、FAIL があれば **1バイトも書かずに落ちる**
（`build.py; insert.py` と繋いだとき、落ちたはずのデータが成果物へ行くのを防ぐため）。

## ファイル

| | |
|---|---|
| `content_p1/p2/p3.py` | 各部の設問データ（唯一のソース） |
| `content.py` | 3部を統合。`Q_FIELDS` が「問題編に印字してよいフィールド」の定義 |
| `check.py` | 機械ゲート14種 |
| `build.py` | reportlab で 問題編／解答解説編 の2 PDF |
| `blind.py` | 盲検証ハーネス（`make` / `reconcile`） |

## 設計上の約束

- **解答は完全別冊**。`content.py` の `Q_FIELDS` に `exp` / `point` / `fix` / `ans` / `model`
  を足した瞬間に「答えが載った問題編」になる。ゲートが構造として検出する。
- **部扉・大問見出しに文法項目名を書かない**。「大問2 仮定法」と書けばその大問は解けてしまう。
  小問の指示（「分詞構文で始めて」等）は本番の設問文そのものなので対象外。
- **各部100点満点**。小問配点の合計が満点と一致することをゲートで担保する
  （合わないと生徒が自己採点できない）。
- 英文和訳・和文英訳は唯一解が無いので、**模範解答＋採点要素**で採点する。
  採点要素は「模範解答の言い回し」ではなく「日本語のどの意味を落としていないか」で書く。
  前者で書くと、本書自身の別解が本書自身の基準で満点にならない（初版で14問中8問）。
- 大問構成は一次情報（大学公式の過去問PDF＋駿台の設問別分析）で裏を取ること。
  初版は「同意文書き換え」を独立大問に置いたが、対象13大学のどこも出していなかった。
  逆に**英文和訳は調べた全大学が出す**最も普遍的な記述形式。
- **大学名を「○○大型」と書かない**（形式の再現を意味してしまう）。難易度の目安なら「〜レベル」。
  一次情報（実際の過去問PDF）で確認した対象校の出題実態:
  誤り指摘＝東大4(A)と東北大のみ／語句整序＝東大1(B)・一橋Ⅱ・東北大・名大・筑波Ⅲ・千葉／
  記述式空所補充＝千葉大問3・一橋2026Ⅱ・北大大問3／英文和訳＝ほぼ全大学／
  和文英訳＝東大2(B)・京大Ⅲ・阪大Ⅳ・東北大Ⅳ（神戸・筑波・広島・横国・名大・九大・北大は近年なし）／
  **自由英作文＝ほぼ全大学が毎年出すが本書は0問**。
- **形式を「○○大型」と名乗る前に実物を見ること**。例: 東大4(A)の正誤問題は
  「約600語の英文を5段落に割り、各段落の(a)〜(e)から1つを記号で選ぶ（訂正は書かせない）」で、
  よくある「単文＋下線部(a)-(d)＋訂正を記述」は私大型。名乗りと中身がずれる。
- 文法の独立大問を出す難関国公立はほぼ無い（東北大の文法正誤も読解大問内の小問）。
  本書は「文法を単独で鍛える演習書」であって「一回分の入試の再現」ではない、と前書きで明言する。

## 検証（この順で）

1. `check.py` の機械ゲート — 確定的に判定できるものを全部ここで潰す。
2. `blind.py make` → 3人の独立ソルバーが**正解を伏せた状態で**解く
   （A=唯一解／B=第2正解探し／C=英文の自然さ・出題成立性）→ `blind.py reconcile` で厳密照合。
   **全員が鍵と違う＝本物の鍵誤りの最強シグナル**。
3. 解説の事実性レビュー・本番忠実度レビューを並列で。
4. `_pdf_qa.py` で実描画 QA →代表2〜3ページだけ目視。

## ★最大の学び: 「解答漏洩」は文字列一致では捕まらない

初版は「答えの文字列が問題編の他の場所に無いか」だけを見ていた。実際に起きていたのは
**答えの文字列は一致しないのに、文法の形が別の設問の問題文に丸見え**という型で、
機械ゲートも3人の盲ソルバーも全部素通りした（冊子レビューで5組発見）。

| 教えている側 | 教えられている側 |
|---|---|
| 大問2の問題文 `the harder it became` | 大問3の答え `the` |
| 大問4の英文 `Faced with a shrinking budget` | 大問3の答え `Seen`（分詞構文の態） |
| 大問2の語群 `Had it not been for` | 大問3の答え `Had he been` |
| 大問2の問題文 `does not necessarily mean that` | 大問5の採点ポイント2つ |

**盲ソルバーは「その問題を解く」ので他ページを見ず、構造的に検出できない。**
→ `check.py` の G15 が ▶ポイント（その問題で学ぶこと）の類似度を測り、
同一部内で同じ項目を2度問うている組を FAIL にする。部をまたぐ組は WARN（難易度の逆転を目視）。

## 実際に踏んだ罠（次回のために）

- **表紙や前書きに「N問」と手で書かない**。大問を差し替えて9問減ったのに表紙だけ 112問 のまま
  刷る寸前だった。問数・配点・満点は必ず実データから計算し、PDF から読み直して突き合わせる。
- **前書きの採点規定と各問の配点を機械で照合する**（G16）。「ポイント1つにつき1点」と書いて
  英文和訳だけ2点にしていたため、そのとおり採点すると各部9点が消えた。
- **tell を潰す修正が別の欠陥を作る**。「正解の下線部が単独最長」を潰すために下線を組み替えたら、
  時制の破綻を2件（`had set earlier last month`／`in recent years` と現在形の衝突）作り込んだ。
  組み替えたら必ず盲で読み直す。
- **和文と欧文の間にスペースを入れる**（`wa_ei()`）。無いと「用いてIt is」と詰まる。

- **reportlab は Paragraph の連続空白を1つに畳む**。記入欄の空所を半角スペースで書くと
  `(        )` が `( )` まで縮んで**書き込めない冊子**になる。空所は必ず `&nbsp;` で作る。
- **1問は `KeepTogether` で括る**。括らないと日本語文だけ前ページに残り、対応する英文が
  次ページに行く分断が実際に出た。
- **ヘッダの大問名は first と last の両方を持たないと必ずズレる**。
  そのページで大問が始まるなら「最初の」大問、始まらない続きのページは「直前ページの最後の」大問。
  片方だけだと、1ページに大問4と5が同居した瞬間に嘘の見出しになる。
- 日本語ファイル名は NFD/NFC 不一致で FileNotFound を起こす。**英数字名で書いてから mv**。
- 整序の tokens は**多重集合で解答と機械照合**する。1語多い／少ないは目視では絶対に見つからない
  （実際に1問、余分な `are` が入っていた）。
- 解答が**別の大問の英文にそのまま印字**される事故が実際に起きた（`did not tell`）。
  答えの文字列が問題編の他の場所に無いことを機械で走査すること。
