## 0. この仕様で作るもの

1. **英語長文**（kind = `english_long`）… 長文読解クラス（月曜3限 Lv.1／火曜3限 Lv.2／金曜3限 国公立コース）に、2日に1回を目安に「クラスの宿題」として自動で配られる4択の長文問題（1回の宿題は本文1本）。レビュー済みの本文がその単元に4本以上そろったクラスから配信が始まる。
2. **習熟度テスト**（kind = `proficiency_test`）… 塾長がクラスに手で配るテスト。自動配信には一切使われない。点数と問題別の正答率は塾長の画面で見る。

どちらも塾のアプリの「科目別ドリル」に取り込まれ、生徒は塾生アプリ／マイページで解く。
**採点はサーバが「正解番号と同じか」だけで行う。** 正解が1つに決まらない問題や、番号が1つずれた正解は、そのまま誤採点になる（英語が読める生徒ほど不正解になる）。

**アプリで出せるのは文字だけ。** 図・グラフ・写真・地図・イラスト・縦書き・傍線・返り点・ルビは出せない。

## 1. 全体の決まり

1-1. 1つの UTF-8 の JSON ファイルにする（英語長文は1セット、習熟度テストは1回分）。文字は NFC。タブと制御文字は使わない（改行 `\n` は可）。

1-2. ★**番号はすべて1始まり。** 正解は `correct_choice_no`（1 = 先頭の選択肢）で書く。
次の名前の欄は書かない（あると検査で落ちる）: `answer` `answers` `key` `good` `correct` `accepted_pairs` `linked_choices` `marks` `points` `multi`
（理由: 0始まりと1始まりを取り違えて「全問が隣の番号で採点される」事故が実際に起きた。0始まりに直すのは取込スクリプトだけ。）

1-3. **1問の正解は1つだけ。** `correct_choice_no` は整数にする（true/false・"3" のような文字列・配列は不可）。

1-4. 選択肢 `choices` は文字列の配列にする。空の選択肢と重複（大文字小文字や空白だけの違いも重複とみなす）は不可。
頭に ①・(A)・A.・1.・ア などの番号を付けない（アプリが ①②③… を付ける）。

1-5. 問題文 `stem`、選択肢、解説 `explanation` には `$` `\(` `\[` を書かない（数式として描画されて崩れる）。金額は「20ドル」「＄20」（全角）と書く。本文 `body` の中の $ は書いてよい。

1-6. HTML（`<b>` など）、Markdown（`**太字**`・`![画像]`）、SVG、画像、URL の埋め込みは不可。

1-7. メールアドレスを書くときは @ を全角 ＠ にする（公開リポジトリの個人情報検査のため）。実在の個人名・生徒名・学校名は書かない。

1-8. **オリジナルであること。**
- 入試の過去問、市販教材、新聞やウェブ記事の文章を写さない（話題や事実は使ってよいが、文章は書き下ろす）。
- note・PDF・神テスト・配布プリントで公開または販売した文章や問題は使わない（生徒が先に見られる）。

1-9. ID（`set_id` `pid` `qid` `test_id`）は、後で1問ずつ直すための名札。ファイル内で重複させない。取り込んだ後は変えない。

1-10. ★**置き場所: リポジトリ（ai-juku-system）の中には置かない。** seed-data/ と docs/ も不可。公開されるため。取込スクリプトはリポジトリ内のファイルを拒否する。
- 英語長文: `~/Desktop/📚 教材/英語/02_長文読解/長文クラス用_科目別ドリル/<Lv1|Lv2|国公立>/<set_id>_<YYYY-MM-DD>/drill.json`
- 習熟度テスト: `~/Desktop/📝 模試・演習/習熟度テスト/<test_id>_第<N>回/test.json`
- 盲検などの記録は、それぞれ同じフォルダの `_review/` に置く。

1-11. 作る側（Codex など）がするのは「作る → 検査を通す → 盲検を記録する」まで。リポジトリの編集・コミット・push と、本番への取込はしない。取込は塾長が行う。

## 2. 本文 (body) の書き方

- 段落は空行（`\n\n`）で区切る。段落番号が要るときは、行頭に `[1]` `[2]` …（半角の角かっこ）を付ける。
- ★**半角かっこの数字「( 1 )」は空所専用。** 空所は、本文に出てくる順に `( 1 )` `( 2 )` … と1回ずつ書く。`(1)` を段落番号や注の番号に使わない（アプリが空所として黄色く光らせる）。空所を問う設問の問題文は「( 1 ) に入れるのに最も適切なものを選びなさい。」のように「( k )」で始める。
- 下線部は `［A：underlined words］` と書き、問題文では「下線部A」と呼ぶ。
- 文を入れる位置を問う問題では、本文に `［ア］［イ］［ウ］［エ］` を置き、選択肢を「［ア］」…にする。
- 表は「［表］」と1行書き、その下に1行ずつ、列を「｜」で区切って書く。1行目は見出しにし、どの行も列の数をそろえる。
  ```
  ［表］
  曜日｜開館時間
  月〜金｜9:00〜18:00
  土｜10:00〜15:00
  ```
- グラフ・図・写真・地図・イラストは使わない。「下の図」「図1」「the graph below」のような言い方も不可。数値が必要なら表にする。
- 漢文（返り点・送り仮名）や、縦書きを前提にした問題は不可。

## 3. 英語長文（kind = "english_long"）

```json
{
  "format": "trillion-drill-import/v1",
  "kind": "english_long",
  "set_id": "L1S001",
  "unit": "長文 Lv.1",
  "created": "2026-10-20",
  "author": "codex",
  "copyright": {"original": true, "not_published_anywhere": true, "fact_sources": []},
  "passages": [
    {
      "pid": "P01",
      "title": "Books on Wheels",
      "body": "[1] When the town library closed for repairs, many people worried about losing a quiet place to read. Many residents could no longer reach the building. ( 1 ), the staff began delivering books by bicycle.\n\n[2] ……",
      "body_ja": "[1] 町の図書館が改修で閉まったとき、……",
      "questions": [
        {
          "qid": "P01-Q1",
          "type": "空所補充",
          "stem": "( 1 ) に入れるのに最も適切なものを選びなさい。",
          "choices": ["For example", "In contrast", "As a result", "At first"],
          "correct_choice_no": 3,
          "explanation": "正解 ③ As a result\n【根拠】Many residents could no longer reach the building.\n【訳】多くの住民が建物に行けなくなった。\n【他の選択肢】\n① For example … 前の内容の具体例ではない。\n② In contrast … 対比の関係ではない。\n④ At first … 時の順序を表し、原因と結果の流れに合わない。"
        }
      ]
    }
  ],
  "_review": { "6章の形": "…" }
}
```

- `unit` は次の3つのどれか（1文字でも違うと取り込まれない）。

  | unit | クラス | 本文の目安 | 設問 |
  |---|---|---|---|
  | `長文 Lv.1` | 月曜3限 長文読解 Lv.1（標準・高1/2） | 300〜550語 | 4〜5問 |
  | `長文 Lv.2` | 火曜3限 長文読解 Lv.2（難関・高3） | 500〜800語 | 5〜6問 |
  | `国公立 長文` | 金曜3限 国公立コース 長文読解 | 600〜1,000語 | 5〜6問 |

  語数と設問数は目安で、外れると警告が出る。上限は1本あたり1,500語、設問は3〜6問。

- `set_id` は英大文字と数字で2〜8字（例 `L1S001`）。一度使った set_id は二度と使わない。
- 1ファイルに本文は1〜20本。`pid` は `P01`〜、`qid` は `P01-Q1` の形にする。
- 選択肢はちょうど4つ。`body_ja`（全訳）は必須（生徒には解き終えた後だけ見える）。`title` は任意（60字以内）。
- `type`（設問の種類）は次のどれか: 内容一致／内容不一致（合わないもの1つ）／空所補充／下線部の意味／指示語／段落の要旨／主題・タイトル／推論／文挿入。
  記述・和訳・要約・語句整序・「2つ選べ」は不可。
- 正解の位置
  - ファイル全体で、①〜④ のどれも40%以下にする。
  - 同じ番号の正解を4問続けない。
  - 正解がいちばん長い選択肢である問題は、全体の半分以下にする（超えると警告）。
  - 問題文の語が正解の選択肢にだけ出る（読まずに当たる）問題は警告になる。
- 実在の事実（数字・年・人名・研究結果）を書くときは、`copyright.fact_sources` に出典（資料名・URL）を書き、事実確認の記録（6章）を付ける。

## 4. 習熟度テスト（kind = "proficiency_test"）

```json
{
  "format": "trillion-drill-import/v1",
  "kind": "proficiency_test",
  "test_id": "HSENG01",
  "target": "kosei",
  "subject": "english",
  "subject_ja": "英語",
  "series_ja": "習熟度テスト",
  "round": 1,
  "revision": 0,
  "title": "高校英語 習熟度テスト 第1回",
  "time_limit_min": 60,
  "created": "2026-10-20",
  "author": "codex",
  "copyright": {"original": true, "not_published_anywhere": true, "no_past_exam_text": true},
  "sections": [
    {
      "section_no": 1,
      "title": "第1問 A",
      "body": "第1問 A\nYou are visiting a community center and see this notice.\n［表］\n曜日｜開館時間\n月〜金｜9:00〜18:00\n土｜10:00〜15:00",
      "body_ja": null,
      "questions": [
        {
          "qid": "Q01",
          "stem": "If you want to use the center on a Saturday, you must leave by",
          "choices": ["12:00", "15:00", "17:00", "18:00"],
          "correct_choice_no": 2,
          "explanation": "正解 ② 15:00\n【根拠】土｜10:00〜15:00\n【他の選択肢】\n① 12:00 … 土曜の閉館は12時ではない。\n③ 17:00 … 該当する時刻が無い。\n④ 18:00 … 平日の閉館時刻。",
          "skill": null
        }
      ]
    },
    {
      "section_no": 2,
      "title": "第2問",
      "body": "第2問 次の各文の空所に入れるのに最も適当なものを選べ。",
      "questions": [
        {
          "qid": "Q02",
          "stem": "This is the house (     ) my grandfather was born.",
          "choices": ["which", "where", "what", "whose"],
          "correct_choice_no": 2,
          "explanation": "正解 ② where\n【解説】先行詞 the house の後ろが欠けの無い文 (my grandfather was born) なので、関係副詞 where を使う。\n【他の選択肢】\n① which … 後ろに名詞の欠けが無いので不可 (in which なら可)。\n③ what … 先行詞を取らない。\n④ whose … 後ろに名詞が続いていない。",
          "skill": {"subject": "english", "unit": "関係詞"}
        }
      ]
    }
  ],
  "_review": { "6章の形": "…" }
}
```

- **1ファイル = 1回分 = アプリの1単元。** 単元名は取込スクリプトが「<高校|中学><科目> <series_ja> 第<round>回」の形で作る（例「高校英語 習熟度テスト 第1回」）。直した版を入れ直すときは `"revision": 1` にする（単元名は「…第1回改1」になる）。
- 各欄の値
  - `target`: `"kosei"`（高校生）か `"chugaku"`（中学生）。
  - `subject_ja`: 英語・数学・国語・理科・社会のどれか。
  - `series_ja`: 10字以内で、空白を入れない。
  - `round`: 1〜99。
  - `test_id`: 英大文字と数字で3〜10字。回ごとに別の値にする。
- `sections` が大問。アプリでもこの順のまま、大問の中は `questions` の順のまま出る（並べ替えられない）。
  大問は1〜12個、1つの大問に1〜15問、合計60問まで。
- 各大問の `body` は「第N問」で書き始める（同じ文の本文は重複として飛ばされるため）。
  読む文章の無い大問（文法の小問集など）も、body に指示文を書く。
  `title` は40字以内（例「第1問 A」）。`body_ja` は任意で、提出後に見える。
- `qid` は解答番号として使う。`"Q01"` から出題順の通し番号にする（欠番を作らない）。
- 選択肢は2〜8個（①〜⑧）。
- `not_published_anywhere: true` は必須（このテストの問題と答えを、どこにも公開・販売していないこと）。
- `time_limit_min` は任意（表示用。アプリは時間を計らない）。
- `skill` は任意。その問題を間違えた生徒に練習させたい、科目別ドリルの単元を書く。`{"subject": "english", "unit": "関係詞"}` のように、10章の一覧と完全に一致させる。分からなければ `null` にする（無くても取り込める）。
- 正解の位置は、4択の問題について次を守る。
  - どの番号も40%以下にする。
  - 同じ番号の正解を4問続けない。
  - 4問以上ある大問で、正解を全部同じ番号にしない。
- ★テストの答えは、アプリで提出した直後に生徒に見える。同じテストを複数のクラスで使うときの実施日は、塾長が決める。

## 5. 解説（explanation）— 全問必須

**1行目は必ず「正解 ③ <正解の選択肢の文字列をそのまま>」にする。**
③ は correct_choice_no の丸数字。番号と文字列の両方が合っていないと検査で落ちる（番号のずれを捕まえるため）。

英語長文で必須の見出し:
- `【根拠】` 本文の1文をそのまま書く（要約しない。空白以外が1字でも違えば落ちる。空所の問題は「( 1 )」を含めたまま書く）
- `【訳】` 根拠の和訳
- `【他の選択肢】` 誤答1つにつき1行。「① <選択肢そのまま> … 誤りの理由」の形
- （任意）`【構文】` `【語句】`

習熟度テストで必須の見出し:
- 1行目
- `【解説】`。本文から根拠を引く問題は `【根拠】` でもよい（`【根拠】` を書いた場合は、本文と完全に一致していること）
- `【他の選択肢】`（選択肢が6個以下のとき）

## 6. 盲検（3名）と記録 — 取込の前に必須

手順:
1. 検査を通す。
   `python3 -I ~/Desktop/📝\ 模試・演習/習熟度テスト/_tools/validate_drill_import.py <drill.json|test.json>`
   盲検の記録がまだ無い段階では、E_REVIEW_MISSING 以外のエラーが0件になるまで直す。
2. 盲検用のシートを作る。
   `… validate_drill_import.py --make-blind <フォルダ>/_review/blind_sheet <ファイル>`
   正解・解説・全訳・skill を外したシート（`blind_sheet.md` / `blind_sheet.json`）と、解答用紙のひな形（`answer_template.json`）ができる。
3. 作者以外の独立した解き手3名が、シートだけを見て全問を解き、解答用紙を1人1ファイルで返す（`_review/blind_A.json` など）。
   解き手は別の AI セッション3本でよい。ただし作者と同じセッションや、正解を見たセッションは不可。
4. 3名全員の答えが正解と一致しない問題と、note に「別解あり／正解が2つ／あいまい」と書かれた問題は、どちらかにする。
   - 直す（直したら、その問題の盲検をやり直す）。
   - ファイルから消し、`dropped_qids` に書く。
5. 作者以外が「正解の一意性」を敵対的に読む。4つの選択肢を1つずつ当てはめて、正解が2つにならないか、誤答が別の読み方で正解にならないかを確かめる。記録は `_review/uniqueness.md`。
   英語長文は事実確認も行う（`_review/fact_check.md`）。
6. `_review` を書いて、もう一度 1 を実行する（解答用紙との照合まで自動で行う）。エラー0で完了。

解答用紙（choice_no は1始まり）:
```json
{"format": "trillion-blind-answers/v1", "solver": "A", "date": "2026-10-21",
 "answers": [{"qid": "P01-Q1", "item_hash": "（シートに書かれた値をそのまま写す）", "choice_no": 3, "note": ""}]}
```
- `item_hash` は、本文・問題文・選択肢から計算した値。どれかを直すと値が変わり、その問題の盲検は無効になる（E_BLIND_STALE）。解説だけを直したときは、盲検は有効のまま。
- 解き手の番号が0始まりになっていそうなとき（正解の1つ隣と一致する問題が多いとき）は、E_BLIND_OFFSET で止まる。

`_review` の形:
```json
"_review": {
  "protocol": "trillion-blind/v1",
  "blind": {
    "solvers": [
      {"label": "A", "kind": "ai", "model": "（モデル名）", "date": "2026-10-21", "answers_file": "_review/blind_A.json"},
      {"label": "B", "kind": "ai", "model": "（モデル名）", "date": "2026-10-21", "answers_file": "_review/blind_B.json"},
      {"label": "C", "kind": "ai", "model": "（モデル名）", "date": "2026-10-21", "answers_file": "_review/blind_C.json"}
    ],
    "dropped_qids": []
  },
  "uniqueness_review": {"by": "作者以外のレビュー担当", "date": "2026-10-21", "notes_file": "_review/uniqueness.md"},
  "fact_check": {"by": "作者以外", "date": "2026-10-21", "notes_file": "_review/fact_check.md"},
  "explanation_review": {"by": "作者以外", "date": "2026-10-21"}
}
```
fact_check は英語長文では必須、習熟度テストでは任意。`by` に実在の人名は書かない。

## 7. 使えない形と直し方（塾の既存の模試にある実例）

| 形 | 実例 | 扱い |
|---|---|---|
| 2つ選ぶ・すべて選ぶ | 英語リーディング模試の kind=multi（key [2,4]） | 不可。「AとC」のような組み合わせの4択に作り直す（正解の組み合わせは1つだけ） |
| 選んだ答えで次の正解が変わる | 日本史「（1）あを選ぶ場合は解答番号16に①を…次の（2）には対応する正答がある」 | 不可。作り直す |
| 2マークで1問・複数の組み合わせを正解にする | 公民の marks [9,10]・accepted_pairs | 不可。正解が1つの組み合わせ4〜6択にする |
| 並べ替え | 英語の kind=order（key [2,4,1,3]） | 選択肢を「③→①→④→②」のような完全な順序にした4択にする（正しい順序は1つだけ） |
| 複数マークの統合問題 | 英語の kind=integrated | 1問1正解に分ける |
| 図・グラフを見て答える | 英語の kind=diagram・figure_svg、日本史の写真・地図 | 不可。数値を表（2章）にできるなら可 |
| 数字を直接マークする | 情報Ⅰ・数学の「アイウ」 | 不可。数値の4択に作り直す |
| 前の問いの答えを使う誘導 | 数学の誘導問題 | 前の問いの正解を問題文に書いておけば可（答えに依存させない） |
| 正誤の組み合わせ | 「a 正 b 誤」 | 組み合わせの4択として正解が1つに決まるなら可 |

作り直した問題は、盲検をやり直す。

## 11. 検査のおもなエラーと警告

エラー:
- E_FORMAT … 形式の誤り・必須欄が無い
- E_INDEX_FIELD … answer・key・good・accepted_pairs などの欄がある
- E_CORRECT_NO … correct_choice_no が範囲外、または整数でない
- E_CHOICES … 選択肢の数・重複・空・頭の番号
- E_MULTI_SELECT … 2つ選べ など
- E_CONDITIONAL … 選んだ答えで正解が変わる・前問の答えを使う
- E_FIGURE … 図・グラフ・画像、またはそれへの言及
- E_KATEX … $ など
- E_HTML
- E_EMAIL
- E_BLANKS … 空所番号の並び・どの設問からも参照されない ( N )
- E_UNDERLINE … 問題文の「下線部A」が本文に無い
- E_TABLE … 表の列数がそろっていない
- E_EXPL_HEAD … 解説1行目の番号・文字列
- E_EXPL_EVIDENCE … 根拠が本文と一致しない
- E_EXPL_OTHERS … 誤答の行が無い
- E_POSITION … 正解位置の偏り・連続
- E_UNIT … 単元名
- E_ID … ID の形式・重複
- E_DUP … 本文・問題の重複
- E_SIZE … 数の上限
- E_REVIEW_MISSING … 盲検の記録が無い
- E_BLIND_MISMATCH … 盲検の答えが正解と一致しない・別解の指摘がある
- E_BLIND_STALE … 直した後に盲検をしていない
- E_BLIND_OFFSET … 解答用紙の番号の基準がずれている
- E_SKILL … skill の単元が存在しない
- E_LOCATION … ファイルがリポジトリの中にある

警告:
- W_WORDS … 語数が目安の外
- W_LONGEST … 正解がいちばん長い選択肢である率が高い
- W_GIVEAWAY … 問題文の語が正解の選択肢にだけ出る
