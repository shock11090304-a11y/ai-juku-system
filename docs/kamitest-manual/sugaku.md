# 神テスト 問題作成マニュアル — 数学

<!-- canon:subject-value -->`math`<!-- /canon:subject-value -->

**先に [共通編](README.md) を読む。**
数学は神テストにまだ 1 冊も入っていない。**このマニュアルが最初の 1 冊の契約**になる。
英語 15 冊 (`scripts/book_exam/materials/*/build_*.py`) を型として写し、
下の 3 点だけを数学向けに差し替える — **解答形式・数式の扱い・正解の作り方**。

---

## 1. ★ 最初に読む — 神テストに入れられる解答形式は 2 つだけ

| 形式 | 神テストでの姿 | 数学で使えるか |
|---|---|---|
| `choice` | 1〜N の数字ボタン | ○ **これを主力にする** |
| `short` | 1 行の入力欄。**小文字化した完全一致**で採点 | △ 条件つき (§2) |
| マーク式 (ア=5 / イ=−3 …) | **無い** | ✗ **入らない** |

### なぜマーク式が入らないか (2026-08-14 に実測で確定)

共通テスト型のマーク欄は答えが 1 桁の数字 (ア = 5)。ところが

- `short` にすると **`exam-book-admin-model.mjs` が「正解が数字だけ」を弾く**
  (「選択式の取りこぼし」を捕まえるための砦で、紙教材 835 問の変換で実際に効いている)
- `choice` にすると **PDF には「ア」と出ているのに画面には 1〜10 のピルが出る**。
  しかも **0 のマークが表現できない** (`choice_count` は 2〜10、値は 1 起算)

→ 共通テスト数学IA / IIB の変換器 (`convert_kyotsu_yaml.py`) が 9 科目中この 2 冊だけ
落としているのはこの理由。**スキーマと検証器の設計変更が要るので、指示があるまでやらない。**
今作るなら**マーク式ではない冊子**にする。

---

## 2. `short` を使ってよい場合・いけない場合

採点は **`lower(btrim())` の完全一致 + `accepted_answers` の和集合**。
部分一致も正規表現も無い (共通編 §4)。

| 答え | 判定 | 理由 |
|---|---|---|
| `x = 3` | ✗ | `x=3` / `3` / `x＝3` が全部落ちる |
| `50Ω` | ○ | 単位付きなら「数字だけ」の門をくぐる。`accepted_answers` に `50 Ω` `50オーム` |
| `3` | ✗ | **数字だけの正解は取り込みが弾く** |
| `二等辺三角形` | ○ | 用語は表記が 1 通りに決まる |
| `y = 2x + 1` | ✗ | 空白・順序の揺れが無限にある。4 択にする |

★ **式や数値を答えさせたいなら 4 択にする**のが正解。途中式を書かせたいなら
**PDF に手書きの解答欄を刷る**。ただし**講師用の手書き閲覧画面はまだ無い**
(共通編 §4) ので、添削はその場で紙として見る前提で組む。
神テストの自動採点は「1 通りに書ける答え」だけを引き受ける。

## 3. ★ 数式の書き分け — 解説に LaTeX を書かない

置き場所によって扱いが正反対になる。**ここを混ぜると必ず崩れる。**

| 置き場所 | 表示のされ方 | 書き方 |
|---|---|---|
| **問題 PDF** (設問文・選択肢) | ビルダーが組版する | **LaTeX で書き、刷る前に KaTeX を通す** |
| **`explanation` (画面の解説)** | `textContent` で**素のテキスト**表示 | ★ **LaTeX 禁止。素の記法で書く** |

`\(AB=6\)` と書くと、生徒の画面には **`\(AB=6\)` とそのまま出る**
(共通編 §5)。紙にも `¥(AB=6¥)` と出た事故が既にある。

### 解説で使う素の記法 (この形に統一する)

| 数式 | 解説での書き方 |
|---|---|
| 累乗 | `x^2` `a^(n+1)` |
| 分数 | `(a+b)/2`。入り組むときは「分母を 2 に揃えると」と日本語で言う |
| 根号 | `√2` `√(x+1)` |
| 積分・総和 | 「0 から 1 まで積分すると」と**日本語で書く** |
| 添字 | `a_1` `a_n` |
| 三角比 | `sin30° = 1/2` |
| ベクトル | `→AB` または `ベクトル AB` |
| 不等号 | `≦` `≧` (全角。`<=` と書かない) |

★ **PDF 側の整形は必ず LaTeX 描画の「前」に行う。** 後にすると SVG の path が
本文に漏れる。`passage / stem / choices / explanation` の 4 つを**漏れなく**通す
(1 つ通し忘れると、そこだけ日本語フォントで `¥(…¥)` と出る)。

★ 今の共通ビルダー `_grammar_build.py` は **KaTeX を通さない** (英文法専用)。
数学の冊子を作るなら、`build_html()` に相当する部分で
**KaTeX (または MathJax) の描画を挟んだ数学用ビルダー**を書くこと。
`build_json()` / `run()` の型はそのまま使える。

## 4. ★ 正解を手入力しない

CLAUDE.md の既定方針。神テストでも変えない。

```python
# build_*.py の中で
#   correct / distractors は「LaTeX と sympy 値」の組で持ち、
#   verify() が独立に再計算して照合する
CHOICES = [("\\frac{1}{2}", Rational(1, 2)),
           ("\\frac{1}{3}", Rational(1, 3)), …]
```

- **正解を sympy で再計算して照合する。** 手で書いた答えを信じない
- **誤答が正解と同値でないことも確認する。** 別表記の同値 (`0.5` と `1/2`、
  `√2/2` と `1/√2`) が混ざると**正解が 2 つある問題**になる。
  `simplify(a - b) == 0` で全ペアを見る
- 数値解のときは有効数字を揃える。「四捨五入して小数第 2 位まで」を設問文に明記する

## 5. 解説の形 — 5 段階 (3 行以上)

数学 (理系) プールの正典に合わせる。実例は `seed-data/rikei_kyotsu_math_manual.json`。

```
【方針】どの定理・どの型に持ち込むかを 1 行で。
【立式】何を文字で置き、どの関係式を立てるか。
【計算】途中を飛ばさない。1 行 1 変形。
【答え】最終的な値。単位・範囲つきで。
【補足】よくある誤り / 別解 / 次に同じ型に会ったときの合図。
```

- **英語の 4 セクション (`## 🎯 コアイメージ` …) を数学に持ち込まない。**
  あれは `subject == "grammar"` の冊子だけの契約
- 見出しは `## ` を付けても素のテキストで `## ` ごと出る (共通編 §5)。
  上のように **【】で囲む**方が画面で読みやすい
- 誤答の潰し方は「なぜその値が出てしまうか」まで書く
  (「符号を落とすと 3 になる」)。ただ「誤り」とだけ書かない

## 6. 冊子の標準仕様 (最初の 1 冊はこの形で作る)

| 項目 | 値 | 理由 |
|---|---|---|
| 問数 | 10 問 | 英語 15 冊と揃える。1 回 20〜30 分で終わる粒度 |
| 形式 | 4 択 | §1・§2 |
| 配点 | 全問 2 点 = 20 点 | 均等。難問だけ配点を上げたいなら `points` を変えてよい |
| 制限時間 | 25〜30 分 | 計算量に合わせる。`time_limit_min` は必須 (ゲートが見る) |
| `subject` | `math` | |
| 単元タグ | `SUGAKU1A-…` `SUGAKU2B-…` `SUGAKU3C-…` | 科目区分 + 論点。`[A-Z0-9]+-[A-Z0-9]+` |
| ディレクトリ | `scripts/book_exam/materials/〈ローマ字〉/` | 例 `sugaku_bibun1` |

★ 単元別ドリルと模試を混ぜない。各小問が独立した 4 択は**単元別ドリル**であって
模試ではない。模試を作るなら誘導連鎖 (前問の結果を次問で使う) を入れ、題名で分かるようにする。

## 7. 図・グラフ

- **図は PDF にしか置けない。** 画面には数字ボタンしか出ない (共通編 §0)
- 線と文字は `currentColor`、塗りは中間色 (#3b82f6 / #ef4444 / #22c55e / #f59e0b)。
  PDF は白地なので固定の明色は沈む
- **✓ / ✗ は文字で置かず線で描く** (日本語フォントに無いと PDF で豆腐になる)
- 図に**設問の根拠になる数値**を出すなら、その数値は設問文にも書く。
  図だけにしか無い数値は、PDF の解像度や印刷で読めなくなったときに設問が壊れる

## 8. ★ 機械が見てくれない範囲 (数学で特に危ない)

コミット済み JSON を見るゲート `check_grammar_books.py` は、
**解説の形と正解位置の配りを `subject == "grammar"` の冊子にしか適用しない**。
つまり数学の冊子は、今のところ

- 共通の検証 (番号・ページ・正解の形・配点・PDF の有無と大きさ) … **見る**
- 解説 5 段階の欠け / 正解位置の偏り … **見ない**

→ **数学用の検査を書いたら `check_grammar_books.py` の `subject` 分岐に足し、
必ずコミットする。** 「作ったその場でしか動かない検査」を増やさない。
書かないうちは、共通編 §7 の③層 (人手の敵対的再読) が唯一の砦であることを自覚する。

## 9. 数学で落ちやすいところ

| 症状 | 原因 / 対策 |
|---|---|
| 取り込みが「記述の正解が数字だけです」で止まる | §1・§2。4 択にするか単位を付ける |
| 画面の解説に `\frac{1}{2}` と出る | 解説に LaTeX を書いた (§3) |
| 紙に `¥(AB=6¥)` と出る | KaTeX を通し忘れた項目がある (§3) |
| 正解が 2 つある | 誤答が別表記の同値。sympy で全ペアを照合する (§4) |
| 生徒が全員 0 点 | `correct_answer` を 0 起算で書いた (共通編 §3) |
| 「答えは合っているのに不正解」 | `short` の完全一致採点 (§2) |
