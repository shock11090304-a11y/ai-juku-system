# 神テスト 問題作成マニュアル — 国語 (現代文・古文・漢文)

<!-- canon:subject-value -->`japanese`<!-- /canon:subject-value -->

**先に [共通編](README.md) を読む。**
国語は神テストにまだ 1 冊も入っていない。組み立ては全教科共通の
`scripts/book_exam/materials/_book_build.py` が引き受ける
(実物の型は `materials/sugaku_nijikansu1/build_sugaku_nijikansu1.py`)。
書くのは META と QUESTIONS だけ。本文は META の `passages` に載せる。

---

## 1. ★ 先に決めること — 本文の著作権

国語だけが持つ制約。**このリポジトリは PUBLIC** (共通編 §8)。

- 冊子の PDF は `scripts/book_exam/materials/〈冊子〉/` に**コミットする**運用
  (英語 15 冊がそうなっている)
- つまり **PDF に刷った本文はそのまま世界に公開される**

→ 現代文の本文は次のどれかにする:

| 使ってよい | 例 |
|---|---|
| ○ 自作の文章 | 塾で書き下ろした評論・随筆 |
| ○ 著作権の切れたもの | 著作者の没後 70 年を過ぎた作品 (青空文庫等)。**出典と底本を `build_*.py` の冒頭コメントに書く** |
| ○ 短い引用 (出典明示・主従関係あり) | 論の一部を引く形。本文まるごとは引用にならない |
| ✗ 入試過去問・市販問題集の本文をそのまま | 公開リポジトリに置けない |

★ どうしても他人の本文を使う冊子を作るなら、**その冊子だけリポジトリに入れない**
(`.gitignore` して Supabase Storage へ直接上げる) 判断が要る。
その場合コミット済みゲート (`check_grammar_books.py` / `check_pdf_canon_match.py`) が
効かなくなるので、**なぜ外したかを `docs/` に書き残す**こと。

古文・漢文の原典 (源氏物語・史記など) は著作権が切れているので問題ない。
ただし**現代語訳・注釈・校訂本文には著作権がある**。訳は自分で付ける。

## 2. 本文の置き方

- **本文は PDF にしか置けない。** 画面に出るのは「第N問」と数字ボタンだけ (共通編 §0)
- **本文に行番号を振る** (5 行おき)。解説が「12〜14 行目」と指せるようにする。
  行番号が無いと、解説の根拠を生徒が本文の中で探せない
- 1 ページに本文、次のページから設問、という並びにして、`page` は
  **設問が載っているページ**を指す (本文のページではない)

### 縦書きにするか

本番形式は縦書きだが、**最初の 1 冊は横書きで作る**ことを勧める。理由:

- 刷り上がり PDF から読み返して正典と逆照合する検査
  (`check_pdf_canon_match.py`) は、PDF のテキスト抽出に依存している。
  縦書きにすると抽出順が崩れて**照合が通らなくなる**ことがある
- 縦書きで作るなら、**先に 1 冊刷って `check_pdf_canon_match.py` が通ることを確かめる**。
  通らないなら照合の層 (共通編 §7 の①) が丸ごと死ぬので、
  縦書きを諦めるか、抽出側を直してから進む

### ルビ

- **組版で解決してから刷る。** `|漢字《かんじ》` のような生の記法を PDF に残さない
  (共通テスト国語の変換で、ルビ記法が残ったままの組版前データが冊子になりかけた実例がある)
- HTML なら `<ruby>漢<rt>かん</rt></ruby>`。刷る前に必ず目で見る

## 3. 解答形式 — `short` は用語だけ

採点は完全一致 (共通編 §4)。国語は**表記の揺れが最も大きい教科**なので、
`short` の使いどころを間違えると正しく書けた生徒が不正解になる。

| 答えさせるもの | 形式 |
|---|---|
| 内容説明・理由説明・主旨 | **4 択 / 5 択** (`choice`) |
| 傍線部の言い換え | **4 択** |
| 文法・品詞・活用形の名前 (「連用形」「断定の助動詞」) | `short` ○ |
| 古語の意味 | `short` △ — 別解を全部 `accepted_answers` に書けるなら |
| 書き下し文・現代語訳 | **✗ `short` にしない。4 択にする** |
| 記述 (30〜60 字) | **✗ 自動採点できない。PDF に手書き欄を刷る** (共通編 §4) |

★ 記述の練習をさせたいなら、**手書き欄つきの PDF + 選択式の設問**という組み合わせが
現実的。ただし**講師用の手書き閲覧画面はまだ無い** (共通編 §4) ので、
記述の添削はその場で紙として見る前提で組む。

★ `short` にするときは `accepted_answers` を惜しまない。
「連用形」「れんようけい」、「断定」「断定の助動詞」— 生徒が書きそうな形を全部入れる。

## 4. 解説の形

英語の 4 セクションは `subject == "grammar"` 専用。国語は次の形に統一する
(見出しは `## ` ではなく **【】**。素のテキストで表示されるため — 共通編 §5):

<!-- canon:headings -->
```
【設問の型】傍線部の理由説明 / 空欄補充 / 主旨 — どの型かを最初に名乗る。
【本文の根拠】12〜14 行目「…」 ← ★ 本文からの引用は一字一句そのまま。
【正解の理由】根拠の一文と選択肢のどこが対応するかを言う。
【誤答の切り方】1. …— 本文に無い / 言い過ぎ / 因果が逆 / 対象がずれる。
【次に使える型】同じ型に会ったときの合図を 1 行。
```
<!-- /canon:headings -->

**5 つが順番どおりに 1 回ずつ。1 つでも欠けたら build が落ちる。**

★★ **解説が引用する本文は、本文に実在させる。要約を「」で囲まない。**
これは英語プールで `audit.py` が全数照合しているのと同じ規律。
神テストの国語にはまだその検査が無いので、**人が全数見る**しかない。

★ 誤答の切り方は「本文に無い」「言い過ぎ」「因果が逆」「対象がずれる」のように
**型の名前**で言う。「なんとなく違う」は解説ではない。

## 5. 冊子の標準仕様 (最初の 1 冊はこの形で)

| 項目 | 値 |
|---|---|
| 問数 | 現代文 1 本 + 設問 6〜8 問 / 古文 1 本 + 6 問 / 漢文 1 本 + 5 問 |
| 形式 | 4 択が主力。文法・語の意味だけ `short` |
| 配点 | 内容説明 4〜6 点 / 語句・文法 2〜3 点。合計 50 点前後 |
| 制限時間 | 現代文 25 分 / 古文 20 分 / 漢文 15 分 |
| `subject` | `japanese` |
| 単元タグ | `GENDAI-…` (現代文) / `KOBUN-…` (古文) / `KANBUN-…` (漢文) |
| ディレクトリ | `scripts/book_exam/materials/〈ローマ字〉/` (例 `kobun_jodoushi1`) |

★ **1 冊に現代文と古文を混ぜない。** 生徒は「古文だけやりたい」と探す。
`subject` が同じ `japanese` である以上、**題名で引けるようにする**のが唯一の分け方。

## 6. 正解の一意性 — 国語で一番危ないところ

選択肢が本文の言い換えである以上、**「どれも間違いではないが、最も適切なのは 1 つ」**
という作りになりやすい。これは**正解が 2 つある問題**と紙一重。

確かめ方 (共通編 §7 の③層):

1. 誤答 3 つそれぞれについて、**本文のどの一文が否定しているか**を言えるか。
   言えないものは誤答として弱い → 書き直す
2. 正解の根拠が**本文の一文で完結**するか。2 文以上を継ぎ足さないと正解にならない設問は、
   別の読み方でも成立してしまう
3. 「言い過ぎ」で切る誤答は、**言い過ぎの語 (すべて・必ず・最も) を実際に含んでいるか**。
   語が無いのに「言い過ぎ」と解説していないか

## 7. 機械が見るもの / 見ないもの

**見る** (build 時 `_book_build.verify()`、コミット済み JSON は `check_grammar_books.py`):

- 番号・ページ・配点・単元タグ・正解の形 (記述の正解が数字だけ、なども)
- 解説 5 見出しの欠けと順番 / 誤答の節の番号と選択肢のずれ
- 正解位置の偏りと 3 連続
- 解説に生の LaTeX が混じっていないか
- **記述の正解が問題編の別の場所に印字されていないか (解答漏洩)**
- **刷り上がり PDF に全問・全選択肢が正典どおりのページに在るか**

**見ない** (共通編 §7 の③層。人が全問読むしかない):

- **解説の引用が本文に実在するか**。引用照合はまだ機械化されていない
  (英語プールの `audit.py` に相当するものが神テストにはない)。
  書いたら `check_grammar_books.py` の `subject` 分岐に足し、**必ずコミットする**
- **正解の一意性** (§6)
- 本文の著作権 (§1)。機械では判定できない

## 8. 国語で落ちやすいところ

| 症状 | 原因 / 対策 |
|---|---|
| PDF にルビ記法が生で残る | 組版前のデータを刷った (§2) |
| 逆照合ゲートが通らない | 縦書きでテキスト抽出順が崩れた (§2) |
| 正しい書き下しが不正解 | `short` の完全一致採点。4 択にする (§3) |
| 解説の引用が本文に無い | 要約を「」で囲んだ (§4) |
| 公開してはいけない本文を公開した | §1。**push した時点で履歴に永久に残る** |
