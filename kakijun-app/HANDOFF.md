## 1. 最重要: 設計の分離 (ここを混ぜると必ず破綻する)

今日いちばん時間を溶かした原因は、**お手本の見た目と判定を同じデータで兼ねていた**こと。
字形を直しても直しても別の所が崩れ、塾長を何度も往復させてしまった。現在は完全に分離済み。

| 層 | 実体 | 役割 | 触るときの注意 |
|---|---|---|---|
| **お手本の字** | フォント (Klee One サブセット `public/fonts/KleeOne-subset.woff2` 23KB) | 画面に見える字。`renderGuide.renderBackground` が `fillText` で描く | **線データで描き直さないこと**。字形が崩れる元凶 |
| **書き順の案内** | 番号 + 書き出しの点 + 向き矢印のみ | どの画から書くかを示す | **画の経路を線でなぞって見せない** (§下記) |
| **判定** | 線データ `src/data/characters/*.json` (非表示) | 書き順・書き出し・方向の判定 | 見た目の責任は無い。当たり判定と割り切る |

### ★ 経路を線で見せてはいけない (PR #39)
お手本 (フォント) と線データの経路は一致しない。経路を描くと「お手本と違う線」を
子どもに見せることになり、「なぞり方がおかしい」となる。塾長の判断で**経路表示は廃止**。
書き順は塾長提供のなぞり書きプリントと同じ「番号 + 書き出し」方式で示す。
`renderGuide.ts` の `dottedStroke` と `playDemo` は削除・停止済み。**復活させないこと。**

### ★ お手本は消さない (PR #37)
「何度でも練習できるように」との方針。レベルに関わらず常に同じ濃さ (`GUIDE_SOLID`) で表示する。
薄くするのも「消えた」のと同じ。
なお**消していた真犯人は描画側だった** — §5 の canvas.width の項を必ず読むこと。

### ★ 例外は運筆 (せんのれんしゅう) だけ (2026-08-17)
運筆は「字」ではないので手本フォントに字形が無い。文字コード (〽 ◎ 🪜 ⛰) を借りて
いるだけなので、フォントで描くと**絵文字のはしごや山**が出る。しかも判定する線とは
別物だった。運筆に限りお手本を線データから描く。この場合お手本と判定が同一データに
なるので、上の「経路を見せない」で避けたかった問題 (お手本と違う線を見せる) は起きない。
`PracticeScreen` が `type === 'unpitsu'` のとき `char` を渡さないことで切り替える。

## 3. 残っている課題 (優先度順)

1. **書き出しの点がお手本の墨から浮いている画が 104 ある** (`tools/_start_dots_baseline.txt`)。
   経路表示をやめた今、書き出しの点は書き順を伝える唯一の手がかりなので、
   浮いている画は「何も無いところを指して『ここから書いて』と言っている」状態。
   悪い順に ゆ22% / ヒ20% / と20% / き19% / セ19% / る18% / ふ18% …。
   原因は線データの字形がフォントと別物なこと。`refit-glyphs` は進行方向と直交にしか
   寄せられないので、始点が墨の外にある字は動かせない。**字形の作り直しが要る**
   (`tools/dump-masks.mjs` + `tools/trace_all.py` の経路探索でやる)。
   ★baseline は「許可した一覧」ではなく「直っていない一覧」。直したら行を消す。
2. **線データの忠実度は 74.8%** (`npx vite-node tools/refit-glyphs.mts` で測定)。
   1 と同じ原因。輪の多い字 (そ・ぬ・ゆ・る・す) と き・な が残っている。
   ★合わせ込みには verify が入っている: 墨に寄せた結果、判定エンジンが通らなく
   なる字 (え・す・ん) は自動で元に戻る。忠実度の数字だけ見て入れ替えないこと。
3. **判定エンジンの逆走検知が鋭角に弱い**。輪の多い字でトレース精度を上げると、
   手ぶれを逆走と誤判定する。曲率対応にする改修が本丸。1 を進めるとここに当たる。
4. **実機での確認が未了**: Apple Pencil の筆圧・手のひら誤爆・音声・回転・オフライン。
5. **音声は TTS 頼り**。`public/audio/README.md` の命名で肉声 mp3 を入れると差し替わる。
6. 目視QAは `node tools/qa-sheet.mjs` で全字ぶん撮れるようになった。
   2026-08-17 夜に ひらがな80・カタカナ80・数字11・運筆12 を一通り目で見た。

## 4. 作業手順 (毎回これを守る)

```bash
cd /home/user/ai-juku-system/kakijun-app
npm install                       # コンテナを作り直したら必要

# 検査 (★入口はこの1本。落ちたら出荷しない)
npm run gates                     # 型検査・単体830・ビルド・E2E8・字形2種

# 目視QA (★検査が緑でも見た目が壊れていることがある。出す前に必ず自分の目で)
npx vite preview --port 4173 &
node tools/qa-sheet.mjs --out /tmp/qa          # 子どもが見る画面そのものを全字撮る
npx vite-node tools/render/overlay-sheet.mts   # お手本と判定線を重ねる

# 出荷 (★ これを忘れると本番に反映されない)
node tools/publish-to-repo.mjs    # ビルド → リポジトリ直下 /kakijun/ へコピー
cd .. && git add -A && git commit && git push -u origin <branch>
```

- `/kakijun/` は**ビルド済み成果物をリポジトリに入れて**配信している。
  ソースを直しただけでは本番は変わらない。必ず `publish-to-repo.mjs` を回す。
- push 先ブランチは `claude/new-session-*`。main へは PR 経由。

## 5. 落とし穴 (実際に踏んだもの)

- ★★ **canvas.width への代入は「同じ値でも」中身を消す** (HTML 仕様)。
  `CanvasSurface.layout()` は ResizeObserver のたびに再代入していたが、描き直しは
  「寸法が変わったときだけ」だったので、**2字目からお手本もマス目も真っ白**になっていた。
  2026-08-17 に修正 (寸法が同じなら canvas に触らない)。塾長が繰り返し言っていた
  「お手本が消える」の正体はこれ。#36 #37 はデータ側を常時表示にする対策で、
  消していた張本人には届いていなかった。回帰テストは E2E で**背景層の画素を数える**
  (DOM を見ても分からない。1字目は正常なので「戻って2字目」まで見ること)。
- ★ **見た目の事故は自動テストをすり抜ける**。判定の許容幅が広いので、お手本が
  真っ白でも絵文字でも 830件は緑のまま通った。**必ず画面を撮って自分の目で見る**
  (`tools/qa-sheet.mjs`)。
- ★ **字形を測るツールは、アプリと同じ条件で描くこと**。refit-glyphs は 0.88em・
  中央に描いてお手本としていたが、アプリは 0.86em・y=0.52。別の字に合わせ込んで
  いたので、忠実度 76% という数字自体が誤りだった (実際は 49.3%)。
- ★ **手本フォントを system の名前 ("Klee One") で引かない**。コンテナを作り直すと
  フォントが消え、**黙って代替フォント (IPAGothic 等) を測る**。その状態で
  `refit-glyphs --apply` を回すと全文字が静かに壊れる。`tools/ref-font.mjs` が
  出荷している woff2 を読み、効いていなければ例外で止める。字形を扱う新しい
  ツールは必ずこれを使うこと。
- ★ **運筆 (せんのれんしゅう) に手本フォントは無い**。文字コード (〽 ◎ 🪜 ⛰) を
  借りているだけなので、フォントで描くと絵文字が出る。運筆はお手本を線データから
  描く (お手本と判定が同一データなので PR #39 の問題は起きない)。
- **「直っていない」の切り分け**: ホーム右下のビルド刻印を見る。刻印が古ければ配信の問題、
  新しければデータの問題。これを入れるまで何往復もした。
- **キャッシュ**: `/kakijun/` は拡張子が無いので `vercel.json` の `/(.*\.html)` ルールに当たらない。
  個別に no-cache を指定済み (#32)。PWA なのでリロードは**2回**必要 (1回目で取得、2回目で切替)。
- **`vercel.json` に未知のキーを足さない** (`comment` 等)。スキーマ検証で落ちてデプロイが止まる。
- **長さ0の画は判定エンジンを固める**。`step()` に下限を入れ、退化画を弾く検査も追加済み。
- **コンテナから本番 URL へは出られない** (プロキシ制限)。配信確認は塾長の画面かビルド刻印で。
- **`.claude/` は gitignore** される。ルールや手順はリポジトリ内 (この文書等) に書く。

## 6. 検査・調査ツール

| ツール | 用途 |
|---|---|
| `tools/render/compare-sheet.ts` | 手本フォントと線データを左右に並べた比較シート |
| `tools/render/contact-sheet.ts` | 線データだけの一覧 (`NOREF=1` / `CELL=` で寸法可変) |
| `tools/refit-glyphs.mts` | 忠実度 (線が手本の墨に乗っている割合) の一括測定 |
| `tools/dump-masks.mjs` + `tools/trace_all.py` | 手本の墨から中心線を経路探索して制御点を抽出 |
| `tools/check-mark-clearance.mts` | 濁点・半濁点が基字に食い込んでいないか |
| `tools/gen-derived.mts` | 濁音・小書きを基字から生成 (べき等) |
| `tools/run-all-gates.mjs` | ★検査の入口。これ1本で全部回る (`npm run gates`) |
| `tools/qa-sheet.mjs` | ★実アプリの練習画面を全字撮って一覧シートにする (目視QA) |
| `tools/render/overlay-sheet.mts` | お手本と判定線をアプリと同じ条件で重ねる |
| `tools/check-start-dots.mts` | 書き出しの点がお手本の墨に乗っているかの全数検査 |
| `tools/fit-marks.mts` | 濁点・半濁点をフォントが打つ位置へ実測して合わせる |
| `tools/ref-font.mjs` | ★手本フォントの供給元。出荷 woff2 を読み、効かなければ止める |

手本フォント Klee One は OFL。`~/.fonts` にインストールして QA に使っている
(コンテナ再作成時は Google Fonts から再取得する)。

## 7. 次のセッションへの申し送り

塾長は**修正の往復が多いことに強い不満**を持っている。以下を守ること。

1. **出す前に自分の目で実画面を見る**。Playwright でスクリーンショットを撮ってから報告する。
   検査が緑でも見た目が壊れていることがある (今日それで何度も差し戻された)。
2. **数値だけを根拠にしない**。忠実度95%でも見た目が変だった例がある。
3. **直せないときは正直に言い、代替案を出す**。塾長は「できないなら載せないで」と言ってくれる。
4. 塾長の提案 (例: 「見本の画像の上から書かせればいい」) は**正しいことが多い**。まず検討する。
5. **「検査が緑」を報告に使わない**。2026-08-17 の事故は 829件緑のまま本番で
   真っ白だった。報告するのは「何を自分の目で見たか」。
6. 判定のデータをいじったら、**必ず `npm run gates` と目視QAの両方**を通す。
   数値 (忠実度) が上がっても、判定エンジンが通らない形になっていることがある。
